# Поиск без дополнительных платных сервисов

Проект работает на backend Amvera и не требует домашнего компьютера для сбора данных. Дополнительные подписки, сервисы CAPTCHA и платные API для поиска удалены. Оплата самого хостинга определяется вашим тарифом Amvera.

## Что происходит при подборе

1. Проверяются уже полученные свежие предложения. Полная сборка требует всех восьми категорий и общей стоимости не выше бюджета.
2. Если выбран Avito, выполняется короткая попытка поиска на нём. Отказ этой площадки не останавливает остальные источники.
3. Сначала параллельно ищутся предложения по всем недостающим категориям на двух доступных магазинах. В очереди приоритетны Регард и KNS, которые отвечали при проверке Amvera. Затем пробуются остальные выбранные источники и более доступные модели. Ограничение источников без Avito соблюдается, если пользователь отключил расширение поиска.
4. Сетевые запросы идут параллельно в ограниченном числе потоков; результаты сохраняются в SQLite последовательно. Один отказавший источник не мешает сохранить ответы остальных.
5. Для выбранной конфигурации отдельно проверяются страницы товаров. После изменения цены снова проверяется весь бюджет, питание и совместимость.

## Если готовый ПК не найден

Пользователь видит восемь отдельных категорий, полученные предложения, их сумму и остаток денег. Для недостающих деталей показаны плановые бюджеты и ссылки на магазины, Google, Яндекс, Bing и DuckDuckGo. Плановый бюджет категории не выдаётся за найденную цену. Даже частичный список не содержит сочетания CPU за 10 тысяч и GPU за 41 тысячу при общем бюджете 50 тысяч.

Ссылки на поисковики имеют вид `RTX 3050 6GB site:avito.ru`. Их можно открыть с телефона или другого компьютера. Это обычное посещение поисковика; устройство пользователя не становится агентом сервера. Поисковые описания и цены «от …» не участвуют в расчёте.

Если площадка возвращает CAPTCHA или ограничивает IP Amvera, гарантировать автоматическое чтение всех её цен бесплатно невозможно. Сервер сообщает об этом, использует доступные магазины и сохраняет найденные результаты. Готовая сборка не создаётся из выдуманных объявлений или цен.

## Поиск цен для апгрейда

Интерфейс запускает долгий поиск через серверные задачи: `POST /api/search-jobs`, затем короткие `GET /api/search-jobs/{id}`. Очередь ограничена четырьмя задачами, выполняется одна одновременно. Номер задачи сохраняется в текущей вкладке, результат — в SQLite. При сетевом обрыве сайт продолжает получать ту же задачу. При перезапуске процесса backend незавершённый поиск отмечается прерванным, а завершённые результаты остаются доступны. Это работает в одной реплике backend и не требует Redis, дополнительного контейнера или платной очереди.

Помимо браузера, сервер умеет искать ссылки через обычный HTTP и публичную RSS-выдачу Bing ([описание Bing](https://blogs.bing.com/search/2005/1/RSS-Feeds-for-Search-Results/)). Описания результатов не превращаются в цены: каждый товар читается на самой площадке. Отказ поиска магазина и отказ его страниц товаров учитываются отдельно. Подключённый CAPTCHA-скрипт на обычной странице сам по себе не считается блокировкой.

Замены выбираются по прогнозируемому приросту в выбранной игре. Для CS2 на AM4 проверяются в том числе 5700X3D и 5800X3D: близость многопоточного синтетического балла к текущему CPU больше не исключает их из поиска. Цены ищутся пакетно на выбранных площадках; Avito участвует вместе с магазинами. Найденная розничная цена не отменяет попытку найти подержанную замену на Avito. Автоматическая оценка продажи относится к заменяемой детали: CPU или GPU в зависимости от ограничения производительности.

Сначала выполняются HTTP-запросы, затем остаётся время на браузер. При отказе Avito по HTTP браузер сразу пробует поиск ссылок через поисковики. Если навигация закончилась тайм-аутом, уже загруженная выдача всё равно проверяется. Поиск ограничен общим сетевым окном 45 секунд; ожидание других запросов и обработка данных могут увеличить полное время ответа. Источники, до которых очередь не дошла, отмечаются как непроверенные.

В результате есть отдельный статус каждой площадки и кнопка обновления. Новые цены, сохранённые наблюдения и недоступный источник различаются. При наличии цены на обычный CPU варианты X3D без цены остаются в сравнении; неизвестная стоимость не превращается в подтверждённую покупку в бюджете. Достижение целевого FPS проверяется по центральному прогнозу, а не верхней границе диапазона.

## Развёртывание на Amvera

Используйте `backend/Dockerfile` и `backend/amvera.yaml`, как описано в README. В Amvera задайте:

```dotenv
OFFERS_BROWSER_ENABLED=true
OFFERS_BROWSER_CHANNEL=
OFFERS_HTTP_WORKERS=2
```

Настройки `FRONTEND_URL`, `CORS_ORIGINS`, `COOKIE_SECURE` и SMTP остаются обычными настройками вашего приложения. Ключи Bright Data не нужны и код их не использует. Если ранее добавляли переменные `BRIGHTDATA_*` или `OFFERS_UNLOCKER_*` в Amvera, удалите их из панели.

Загрузите обновлённые backend и frontend и пересоберите приложения. Локальные изменения автоматически не попадают в запущенный контейнер. `/api/offers/status` показывает режим `public_pages` и последние ответы источников; число сохранённых предложений само по себе не доказывает успешность нового поиска.

В ответе `/api/offers/status` также есть `browser`: установленная версия Playwright, наличие исполняемого файла Chromium и настроенный канал. На Linux сервер выбирает встроенный Chromium, даже если осталась локальная настройка `msedge`. Запускается один браузер одновременно, используется `--disable-dev-shm-usage` для контейнеров с небольшим `/dev/shm`. Это исправляет запуск браузера, но не отменяет ограничений доступа самой площадки.

После загрузки этой версии `/api/health` содержит `search_revision: server-jobs-http-v2`. Если сервер выключен, Amvera возвращает 503; это не ответ парсера. Причина вчерашнего обрыва без журналов не считается установленной. Фоновые задачи защищают интерфейс от потери длинного соединения, но не исправляют остановленный контейнер или нехватку памяти автоматически.
