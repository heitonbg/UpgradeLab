# Биржа всех категорий — итерация 11

Реализовано в существующей бирже UpgradeLab. Сетевые адаптеры, FPS, авторизация и правила UTC/TTL не заменены. Все приведённые ниже цены демонстрации синтетические: это проверка механизма, а не наличие товаров в магазинах.

## Причины ограничений до изменений

Listing уже допускал восемь категорий, но internal_offers требовал Hardware и пропускал только CPU/GPU/RAM. Не было отдельного хранения структурированных характеристик продавца. Число каналов Hardware использовалось вместо числа физических модулей RAM. Условия доставки можно было задать отдельным API, но не через редактор объявления. География не различала самовывоз, конкретные города и всю Россию. Изменение характеристик не участвовало в revision кеша. Проверки размеров корпуса/GPU/кулера отсутствовали.

Сквозные тесты также выявили ошибку внешних поисковых ссылок для собственного источника (у upgradelab нет домена STORES) и ошибочное исключение кулера при проверке без сокета. Для собственной биржи внешние ссылки не генерируются; кулер проверяется с сокетом комплектации.

## Данные и категории

Единственный справочник моделей остаётся Hardware. Добавлена только таблица `listing_details(listing_id, data)` с JSON декларацией продавца, связанная один-к-одному с Listing. ListingDelivery используется повторно. Категорийные схемы находятся в `backend/app/schemas/listing_details.py`, поля интерфейса — `frontend/src/lib/listingDetails.js`. Неизвестные значения не заполняются вымышленными спецификациями.

| Категория | Допустимые характеристики продавца | Условия предварительного подбора |
| --- | --- | --- |
| CPU | Производитель, полная модель, socket, поколение, integrated_graphics | Однозначный существующий Hardware, совпадение модели и сокета |
| GPU | Производитель GPU/исполнения, полная модель, VRAM, length_mm, описание питания | Однозначный Hardware и вариант VRAM; Ti/Super не смешиваются |
| motherboard | Производитель/модель/ревизия, socket/chipset/RAM, форм-фактор, интерфейсы/размеры M.2, свободные M.2 | Доступный технический профиль точной платы или существующая проверенная модель; B450 само по себе не доказывает NVMe |
| memory | Модель, DDR, общий объём, число модулей, частота, DIMM/SO-DIMM/RDIMM/ECC | Согласованные DDR/объём/один-два модуля; настольная память; каналы не заменяют модули |
| storage | Производитель/модель/ревизия, ёмкость, SATA/NVMe, форм-фактор, размер M.2 | Существующий профиль конкретной серии/ёмкости/интерфейса; неизвестный размер не наследует 2280 |

Поля необязательны для публикации. Дополнительные вложенные поля запрещены; числовые значения ограничены схемой. Разъёмы, введённые текстом продавцом, не превращаются в Connectors. Hardware нельзя назначить другой категории, CPU/GPU с другим суффиксом или VRAM. При смене категории старая привязка и характеристики очищаются, если новые не переданы; при смене названия старая привязка Hardware снимается.

## Достоверность

`technical_assessment` содержит отдельные `declared_fields`, `catalog_fields`, `trusted_fields`, `missing`, `contradictions`, `optimizer_eligible`. Состояния: seller_declared, catalog_matched, trusted_profile, insufficient_data, contradictory. Сопоставление Hardware или технического профиля не подтверждает товар, его подлинность, состояние, наличие и цену.

Доверенные структурированные метаданные берутся только из доступного CatalogProduct/StoreOffer точного названия и категории; закрытые прайсы исключены тем же catalog_access. Конфликтующие профили не выбираются произвольно. Контекст fixture_catalog существует только для локальных тестов, HTTP-флага включения фикстур нет. Сведения продавца не могут записать проверку цены или технический trust.

Неполные допустимые предложения видны в поиске, но исключены из автоматического подбора и оценки апгрейда. Противоречивые предложения сохраняются в бирже с объяснением, но не выдаются как безопасный StoreOffer. Б/у SSD проходят прежнюю консервативную проверку модели/SMART-предупреждений, теперь и для собственной биржи; БП/кулер для автоматического подбора по-прежнему нужны новые.

## Создание, редактирование и права

POST `/api/listings` и PATCH `/api/listings/{id}` принимают characteristics и delivery одной транзакцией с Listing/ListingOwner. Если запись доставки падает, незавершённая транзакция откатывается при закрытии DB dependency. PUT `/api/listings/{id}/delivery` сохранён. `delivery: null` удаляет условия. GET `/api/listings` и `/api/my/listings` возвращают характеристики, доставку, оценку и публичное имя продавца.

Публикация и мутации требуют существующую cookie-сессию, чужому владельцу возвращается 404. Публичное представление не содержит email аккаунта, password_hash или сессию. Указанный самим продавцом контакт остаётся публичным по действующим правилам. React отображает значения текстом, опасные URL фото/credentials/private IP отклоняются существующей сетевой политикой без загрузки адреса сервером.

В форме категории меняются её поля. Редактор доставки расположен в той же форме создания и редактирования; неподтверждённые характеристики поясняются. Существующие фото/контакты, обмен и предупреждение о несохранённых изменениях сохранены.

## Доставка и города

Режимы: unknown, meetup, pickup, cities, russia. Город объявления обязателен для новых записей. Для cities нужны известные city_id; для russia список не нужен. Стоимость: null — неизвестна, 0 — явно бесплатная, положительное целое RUB — известная. Дробные/отрицательные/boolean суммы отклоняются. Есть текст условий. checked_at и kind=seller_declared ставит сервер. Существующие записи без mode читаются как cities.

В редакторе выберите способ, добавьте города, выберите «уточняется», «бесплатно» или сумму и сохраните объявление. Смена способа очищает скрытые старые города/стоимость. Авторские условия не выдаются за расчёт перевозчика. Публичная карточка показывает условия и их происхождение.

Общий GeoQuery:

- all оставляет безопасные объявления независимо от географии, без обещания итоговой доставки;
- local требует свежий город продавца/остатка, совпадающий с выбранным;
- delivery допускает локальное получение и свежую заявленную отправку в выбранный город/по России.

Самовывоз/встреча не разрешают отправку в другой город. Все режимы условий допускают локальное получение по действующей политике биржи. TTL подтверждения продавца и географических доказательств остаётся 24 часа; TTL независимой проверки цены не менялся.

## Стоимость и подбор

StoreOffer хранит исходную цену товара. При подборе delivery известная стоимость отправки добавляется к временному кандидату: бюджет учитывает её без изменения исторических данных. null не становится нулём, окончательная сумма покупки остаётся неизвестной. Цены продавца имеют origin/price_trust seller_declared, без price_verified_at; восемь частей дают draft, не complete. Техническая совместимость и доверие к цене различаются.

Все восемь категорий собственной биржи участвуют в существующем оптимизаторе полной сборки при достаточных данных. Известные конфликты форматов платы/БП, длины GPU и высоты кулера исключают сочетание. При нехватке размеров совместимость unknown; слова продавца не являются независимым документальным подтверждением. Добавлен только фильтр известных физических ограничений в существующий выбор, FPS не менялся.

В апгрейде используются только уже существующие сценарии CPU/GPU и платформы (плата/RAM/кулер, где их требует сценарий). Новые сценарии замены SSD/корпуса ради FPS не создавались. Неполные предложения исключаются также из upgrade_market_rows.

Изменение модели, цены, категории, характеристик, города, условий доставки, статуса или владельца инвалидирует revision/проверку результата; cached jobs повторно проверяют живой Listing и доступность профиля. Существенное изменение сбрасывает заявление наличия, если продавец не подтвердил его заново. Исторический snapshot сохранения остаётся неизменным; проданная/удалённая/устаревшая деталь не получает актуальную подтверждённую цену.

## Миграция

Обычный `Base.metadata.create_all` при запуске создаёт listing_details аддитивно; старые строки, IDs, Hardware и ListingOwner не переписываются. Старое объявление без details читается с characteristics={}, без доставки — с неизвестными условиями, и редактируется. Создание таблицы проверено на старой схеме. На рабочей БД миграция в этой итерации не выполнялась. Перед production нужны резервная копия и проверка на копии реальной схемы, затем штатный запуск обновлённого backend.

## Ограничения и production

Реальные товарные интеграции по-прежнему не подтверждены; Chromium для магазинов отключён, Avito не активирован. Доставка остаётся заявлением продавца, перевозчик не интегрирован. Нет независимой проверки состояния/подлинности товара, оплаты/резервирования или защиты от продажи вне платформы. Неизвестные/нестандартные серии и ревизии могут публиковаться, но не подбираются автоматически. Нет второго справочника оборудования. Действующие профили не охватывают все размеры, крепления, AIO/радиаторы и разъёмы. Размеры продавца не превращаются в гарантированную совместимость. Денежный контракт integer RUB сохранён, миграция копеек вне итерации.

Для production требуются разрешённые реальные технические/товарные источники, аудит прав отображения старых данных, резервное копирование и миграционный smoke на копии, нагрузочная проверка частой переоценки собственных объявлений. Коммит, push и deployment не выполнялись.
