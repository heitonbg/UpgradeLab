# PCGameBenchmarks: импорт и GPU-ориентированная оценка

Обновлено: 2026-11-15.

## Источник и тип данных

Используется открытый набор [PC Game System Requirements & Estimated FPS by GPU](https://github.com/emilioagustin83/pc-game-fps-dataset), опубликованный под [CC BY 4.0](https://raw.githubusercontent.com/emilioagustin83/pc-game-fps-dataset/main/LICENSE). Снимок зафиксирован на ревизии 299e6f38ed48eda91235bbc451096f5e6fd62910, дата исходного каталога — 2026-11-01, получение снимка — 2026-11-15. Исходные CSV, README, LICENSE и CITATION сохранены в backend/app/data/external_fps/pcgamebenchmarks/source/; SHA-256 каждого файла записан в source_manifest.json.

**Все FPS в этом наборе имеют тип external_model_estimate. Это не результаты игровых прогонов.** PCGameBenchmarks публикует оценки по видеокарте; собственное описание набора сообщает о калибровке на опубликованных измерениях GameGPU и Notebookcheck. Указанная автором точность не проверялась UpgradeLab и не является гарантией. Данные не содержат достаточных CPU/GPU пар, чтобы считать их FPS конкретного компьютера.

Источник задаёт только 1920×1080, High, нативный рендеринг, без RT, DLSS/FSR/XeSS и Frame Generation. Он не содержит 1% Low. Для других настроек численная оценка намеренно не переносится.

## Математика v4 для внешней кривой

Для каждого профиля сортируются исходные GPU-якоря по PassMark G3D Mark. Кривая FPS должна быть положительной и неубывающей — это проверено на всех 16 441 профилях. Между соседними якорями интерполируются log(FPS) по log(G3D Mark); PassMark служит только горизонтальной осью между опубликованными FPS этой игры. Баллы CPU не используются и не превращаются в FPS.

Отдельные кривые сохраняются для дискретных и интегрированных GPU. Для дискретной карты экстраполяция допускается только до половины самого слабого якоря снизу и до 1,25× самого сильного сверху. Интегрированные результаты маркируются very_low; мобильные GPU, неизвестный класс, недостаточный набор якорей и выход за безопасный диапазон получают отказ от численного результата. Для значения также применяется опубликованный игрой cap, если он есть, и технический верхний предел 360 FPS, используемый источником.

### Реальное покрытие локального GPU-каталога

Проверка `backend/pc_upgrade.db` открывала SQLite в `mode=ro` с `PRAGMA query_only=ON` и рассматривала CS2 как одну из эталонных игровых кривых. Результаты до безопасного сопоставления не следует считать надёжными: прежний классификатор давал число для 328/785 GPU, в том числе смешивая классы. После проверки имён, явного типа источника, баллов и границ число осталось для **196/785 GPU**: 179 классифицированных desktop, 8 integrated и 9 моделей, для которых класс удалось вывести только из точного имени и явного типа PCGameBenchmarks. Для integrated результат имеет very_low confidence.

Остальные 589 записей не получают число по причинам:

| Причина отказа | GPU |
| --- | ---: |
| Ниже минимального безопасного G3D-якоря | 262 |
| Не удалось определить класс устройства | 181 |
| Нет отдельной кривой для workstation | 92 |
| Точный источник указывает другой класс устройства | 49 |
| Нет отдельной mobile-кривой | 4 |
| Выше верхней границы экстраполяции | 1 |

Внутри источника сопоставлено 313 точных названий с согласованным типом; для 32 неизвестных по имени класса найдены точные модели с явно указанным типом источника. Это не означает, что все 32 попали в диапазон FPS-якорей. Незнакомые модели не сопоставляются «по похожести»: например, соседние поколения и мобильные варианты могут иметь существенно разные скорости или лимиты мощности. Отказ от части прежних 328 результатов намеренный: он убирает необоснованные числа. G3D остаётся осью интерполяции внутри игровой кривой, а не эквивалентом игрового FPS.

### Покрытие CPU-требований

В закреплённом пакете есть 15 865 полей минимального и 7 433 поля рекомендуемого CPU; 7 763 поля содержат точную модель, 3 291 — семейство, остальные 12 244 — абстрактное или нераспознанное описание. Сопоставление с текущими 1 434 CPU Hardware-каталога даёт хотя бы одну разрешённую CPU-опору для **4 771 из 16 441 игр**, обе опоры — для 2 864 игр. Точно или частично сопоставлены 4 112 минимальных и 3 290 рекомендуемых полей; ещё 131/102 разрешаются только как поколения/семейства. Неизвестное «Quad Core» не подменяется случайным SKU.

CPU Adequacy сравнивает общий PassMark CPU Mark выбранного процессора с медианой и диапазоном явно перечисленных требований. Показатель непрерывный, неопределённость альтернатив показывается диапазоном, но это не игровой CPU-тест, Single Thread, FPS или bottleneck. Из этих требований нельзя вычислить CPU frame time.

### Режимы данных по каталогу

Из 16 447 выбираемых игр: 19 имеют профиль прежней FPS-модели (одна также имеет строгие измерения пары), 16 427 имеют только внешнюю GPU-ориентированную оценку, одна пока не имеет численной опоры. Всего внешний профиль сопоставлен для 16 441 игры. Для 16 441 × 12 якорей пакет содержит 197 292 сторонних оценки. Наличие оценки игры не гарантирует поддержку каждого из 785 GPU. Полноценный системный FPS для большинства каталога отсутствует; при отказе GPU-кривой или неподдерживаемых настройках возвращается понятная причина, а не фиктивный FPS.

## API и пользовательский интерфейс

POST /api/fps/predict добавляет отдельный объект candidate_v4; старые поля и baseline остаются. Пример для Portal 2 и RTX 3060 (G3D 17 008):

~~~json
{
  "status": "external_model_anchored",
  "confidence_level": "external_model_estimate",
  "measurement_type": "external_model_estimate",
  "gpu_oriented_fps": 325,
  "average_fps": null,
  "one_percent_low": null,
  "cpu_limit_assessed": false
}
~~~

Это значение — оценка видеокарты из внешней модели для 1080p High, а не прогноз всего ПК. В интерфейсе оно отображается отдельно от FPS системы, с названием источника, лицензией и предупреждением. Отсутствующие данные CPU/сцены остаются явными.

При разрешении, пресете или графических параметрах вне источника результат возвращает отсутствие числа и причину. Для внешней модели никогда не заполняются average_fps, one_percent_low, ограничивающий CPU/GPU, прирост FPS или цель сборки. Builder/Upgrader сохраняют свои существующие ограничения и не используют GPU-ориентир как системный FPS.

## Повторяемость, тестирование и ограничения

Команда повторной сборки: `python scripts/import_pcgb_fps.py`. Импортёр пишет source_manifest.json, profiles.json и import_report.json атомарно и не переписывает файлы, если байты не изменились. Он не меняет рабочую БД. Полная сводка crosswalk/CPU Adequacy/game batch сохраняется командой `python scripts/evaluate_fps_v4_coverage.py --sqlite-path pc_upgrade.db --output app/data/benchmarks/fps_v4_coverage.json`; SQLite открывается `mode=ro` и `query_only=ON`. Проверки охватывают происхождение/лицензию, 197 292 значения, монотонность кривых, детерминированность импорта, отказы вне условий источника, API, Builder и Upgrader.

Независимого holdout для этой внешней модели нет; MAE, MdAPE и точность UpgradeLab не заявляются. Набор не подходит для обучения CPU-модели, определения bottleneck, оценки 4K/1440p, RT, апскейлинга или 1% Low. Прежние строгие измерения остаются отдельным источником: 4 сопоставимых прогона одной CPU/GPU пары из одной серии. Массовый импорт расширяет доступность ориентиров, но не превращает их в реальные измерения.


## API, Builder/Upgrader и воспроизводимая проверка (2026-11-15)

`GET /api/games/coverage` сообщает раздельно 16 447 игр, 16 441 внешний GPU-профиль, 197 292 оценки и CPU-требования. Для Builder и Upgrader используется общий `resolve_fps_v4`: точная измеренная пара, затем явно помеченный legacy-профиль, затем отдельный внешний GPU-only ориентир. Внешняя оценка не меняет `average_fps`, `one_percent_low`, bottleneck или достижение цели. RAM не передаётся модели.

Read-only TestClient прогнал 100 последовательных запросов `/api/fps/predict` с реальными Ryzen 5 5600 и RTX 3060 из локальной SQLite: 100/100 ответов 200; 14 профилей legacy, 86 внешних ориентиров, CPU Adequacy доступен в 46 случаях. Пакетная проверка всех 16 441 внешних игровых кривых для RTX 3060 нашла 12/12 числовых якорей и GPU-only оценку в каждом профиле за 0,324 с. Это проверка исполнения и покрытия одной карты, не валидация точности.

Upgrader API на тех же реальных CPU/GPU вернул для God of War RTX 3060 → RTX 4060 изменение GPU-ориентира +20 без полного FPS. Для Ryzen 5 5600 → Ryzen 7 7800X3D он вернул CPU Adequacy 286,2% → 525,0%, без прироста FPS. Отдельно API exact-pair для Cyberpunk 2077 вернул опубликованные 179,13 FPS/136,21 FPS 1% Low (2 строки, одна серия). Полная проверка моделей по независимым сериям невозможна: пригодные измерения принадлежат одной серии. Внутрисерийная leave-one-resolution-out диагностика на одной точке: v2 MAE 28,97 FPS, MdAPE 16,17%; legacy MAE 56,13 FPS, MdAPE 31,33%. Это не независимый holdout и не основание заявлять улучшение точности.
