# Smart PC Builder: проверяемый алгоритмический подбор

AI не участвует. FPS Engine и лицензированные измерения сохранены. Режимы цен offers/reference/hybrid используют существующий технический каталог, совместимость, CPU Mark/G3D Mark и явно датированные цены.

## Цены и исправленный hybrid

offers использует разрешённые доступные наблюдения; это не обещание подтверждённой покупки без повторной проверки. reference использует датированные исходные наблюдения и не пишет их в SQLite как свежие StoreOffer. Hybrid сначала сохраняет существующий вариант по реальным категориям с заполнением пробелов справочными, затем отдельно решает задачу на объединённом пуле. Если расширенный пул даёт лучший допустимый score или ту же производительность дешевле, добавляется явно подписанная справочная/гибридная альтернатива. Основной вариант не вытесняется молча. При невозможности базового расчёта проверяется расширенный пул. Не более трёх разных вариантов.

Прежний регрессионный пример: настоящая RX 6600 и справочная RTX 4060 за 15000 ₽. Категорийный приоритет скрывал более выгодную GPU. Теперь RX 6600 остаётся исходным вариантом, RTX 4060 показывается отдельно с reference-метками и purchase_ready=false. Каждая справочная позиция содержит дату, basis и предупреждение; временные отрицательные offer ID удаляются из публичного результата. Ни справочная цена, ни поисковая ссылка AI не получают статус подтверждения.

## Параметры и цели

Добавлены независимые selected_cpu_id/selected_gpu_id: можно зафиксировать одну деталь. Фильтрация выполняется до ограничения кандидатов и после построения допустимых пар. Все альтернативы соблюдают фиксацию. CPU фиксирует выбранную платформу; UI выбирает его сокет и DDR5 для AM5. Невозможная фиксация не заменяется другой моделью молча. Состояние деталей condition=any/new/used применяется к реальному и справочному пулу. Источники, география и доставка используют существующую программную проверку доказательств.

workload=gaming использует существующую допустимую игровую оценку. workload=cpu_work — **узкий профиль CPU-нагрузки**, proxy CPU Mark и заданный минимальный объём RAM, без обещания скорости конкретного приложения. Это не модель всех рабочих станций: GPU-рендер, ML, монтаж и latency-sensitive workloads не калиброваны. FPS в рабочем профиле остаётся дополнительной игровой оценкой, не рабочим рейтингом.

objective=balanced сохраняет прежний игровой выбор по целевому диапазону; для cpu_work выбирает CPU proxy/стоимость полной конфигурации. performance максимизирует допустимый игровой score/CPU Mark среди рассмотренных полных вариантов. economy выбирает минимальную стоимость полного допустимого варианта; для игры при наличии вариантов, достигающих целевого нижнего FPS, выбирает среди них. Новые objective-ветки используют Pareto-отсечение по полной стоимости и объявленному score; это не аппаратная совместимость и не доказательство игрового превосходства CPU Mark.

## Ограничения поиска

Поддерживающие категории фильтруются по совместимости, качеству, питанию, охлаждению, интерфейсам, размерам и бюджету существующими правилами. Joint search учитывает стоимость всех восьми деталей до выбора CPU/GPU. Неподтверждённые BIOS/размеры/разъёмы не становятся compatible.

CPU/GPU-кандидаты ограничены объединением дешёвых, производительных и эффективных по proxy/цене моделей. Начальные настройки: BUILDER_MAX_CPU_CANDIDATES=48, BUILDER_MAX_GPU_CANDIDATES=48, BUILDER_SECONDS_PER_PROFILE=3.0. После фиксации CPU/GPU лимит не выбрасывает выбранную деталь. В одном профиле рассматривается не более 2304 CPU/GPU-пар; поддерживающие категории имеют прежние короткие списки. Временной предел проверяется между парами после формирования поддерживающего пула, поэтому не является жёстким SLA всего HTTP-запроса. Число платформ/повторных профилей ограничено существующим solve_profiles; глобального byte-level лимита памяти нет. Контейнеру нужен собственный memory limit.

Диагностика solver_diagnostics: размеры исходного/ограниченного пула, examined pairs, time_limit_reached и global_optimum_proven=false. Эвристика не гарантирует глобальный оптимум на больших каталогах. Она может пропустить модель вне shortlist; это явно ограниченный поиск. При полном отсутствии вариантов сохраняется существующий partial/fallback pipeline. Исходный временной лимит не заменяет тайм-аут внешних источников.

На небольшой задаче с единственными поддерживающими деталями и двумя GPU проверены известные полные решения: экономичный 48500 ₽, performance с RTX 4060 — 52500 ₽. Эти цены — **синтетические тестовые данные**, не магазин. Тесты также проверяют восемь деталей, сумму, бюджет, независимую фиксацию GPU при cap=1 и рабочий CPU proxy. Доказательства для всех произвольных восьмикатегорийных каталогов нет.

## FPS

Сохранены measurements.json/evaluation_report.json/sources.json/source_policies.json, лицензии и происхождение. Предыдущая база: 81 наблюдение, 72 конфигурации, 4 игры, 3 CPU, 3 GPU, 2 издателя, 4 серии. Внеигровые/OpenGL/синтетические тесты не превращены в игровые измерения. Продвижение новой FPS-модели не выполнено. Legacy/uncalibrated и insufficient_data остаются действующими состояниями. X3D-бонус не добавлен; независимых контролируемых X3D-данных для калибровки по-прежнему недостаточно.
