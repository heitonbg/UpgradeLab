# Визуальный и функциональный аудит UI — итерация 12

Дата: 10.11.2026. Локальная production preview в Edge; API/UI сценарии — явно синтетические fixtures, реальные магазины/SMTP не использовались. Данные графика апгрейда получены существующим backend на временной SQLite (38 → 119 FPS для фиксированного тестового RDR2/1080p_high), а не нарисованы произвольно. Настоящий XLSX исследован отдельно — REGARD_REAL_FEED.md.

## Инвентаризация страниц/состояний

- Главная, две основные CTA и восемь переходов по категориям.
- Сборка: задача, платформа, ручные/автоматические детали, география/источники, проверка, loading/error, варианты, выбранный результат, сравнение/сохранение, partial/draft предупреждения.
- Апгрейд: импорт/ручной ввод, задача, источники, проверка, анализ, результат, график реальных расчётных FPS.
- Поиск: модель/категории, all/local/delivery, город, источники/тип, сортировка/limit, результаты, empty/error и отсутствие подтверждения.
- Биржа: список/фильтры, карточка, восемь категорий создания, редактирование/доставка, состояния продавца, load-more.
- Аккаунт: вход, регистрация, ограничение 429, восстановление, профиль/настройки, мои объявления, раскрытие исторического сохранения и новый расчёт.

До изменений сохранены `.artifacts/ui-before`, после — `.artifacts/ui-after`. Новая home прежде отсутствовала, поэтому её до-скриншота нет; исходная рабочая страница была конфигуратором. До-скриншоты покрывают биржу, карточку, восемь форм, доставку, поиск/результат конфигуратора, а не выдуманный «старый homepage».

До: 91 измерений. После: 98 для биржи/создания/редактирования/доставки/сборки и 98 для расширенного набора страниц; всего 196. Ширины: 320, 375, 390, 768, 1024, 1440, 1920 px. Проверены document scrollWidth и внутренний scrollWidth диалогов — горизонтального переполнения нет. JS pageerror — 0. Восемь форм успешно отправлены, доставка изменена; выбран вариант сборки, окно закрывается, итоговая панель проверена отдельно.

В расширенном smoke работают поиск/геофильтр/сортировка, пустой результат, отказ источника, регистрация и 429, письмо восстановления (мок), профиль, раскрытие/пересчёт сохранения без удаления истории. Проверен перенос БП из поиска в существующую ручную сборку. CPU/GPU по-прежнему выбираются парой в вариантах: отдельного закрепления одной модели новое UI не обещает. Для шести дополнительных категорий переносит offer_id, город/режим/ценовой фильтр и источник; сервер заново определяет цену и совместимость. Непригодное предложение не получает активную кнопку выбора.

Длинный список из 64 mock-объявлений сначала отображает 24, после «Показать ещё» — 48; поиск по всей выборке работает. Повреждённая фотография даёт нейтральный SVG, без чужой модели. Декоративные изображения подписаны/имеют alt. Tab переводит фокус на рабочий элемент; Escape/ловушка фокуса и предупреждение несохранённых изменений используют прежние Modal/формы.

Артефакты: `.artifacts/ui-after/report.json`, `pages-report.json`; скрипты `.artifacts/iteration12-ui-before.py`, `iteration12-ui-after.py`, `iteration12-pages.py`. В actions не сохраняются пароли/токены. Это не тест настоящей SMTP-доставки, провайдера или конкретного устройства пользователя.

## Изображения и performance

Все 30 WebP повторно открыты Pillow и проверены на format/dimensions, существование и размер. 11 изображений главной проверены в DOM: загрузились, alt задан. Hero имеет high fetch priority и responsive picture; вне первого экрана — lazy categories. Width/height и размеры контейнера фиксированы. Caption не выдаёт иллюстрацию за точное фото товара.

Максимальный CLS в зафиксированных локальных навигациях — 0.000174. Наблюдавшийся LCP первой локальной главной — 304 мс. Это одна навигация в локальной preview с мок API и без throttling, не семь независимых mobile cold-start тестов, не Lighthouse score и не production SLA. Изменение viewport не является новой загрузкой страницы.

Production: JS примерно 339 KB / 102 KB gzip, CSS примерно 99 KB / 21 KB gzip; исходный baseline был JS 323 KB / 98 KB gzip и CSS 73 KB / 16 KB gzip. Новых тяжёлых frontend-зависимостей нет. Набор всех 30 WebP — 548 526 bytes, максимум 96 126 bytes; hero/category не требуют PNG в production. DOM длинного списка ограничен порциями, сортировка не мутирует исходную выдачу. Реальная задержка production API/медленных устройств не измерялась.
