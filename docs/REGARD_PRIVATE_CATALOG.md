# Закрытый локальный просмотр прайса Регарда

Проверено: 11 ноября 2026 г. Этот экран предназначен владельцу для просмотра локально импортированного XLSX. Он не является публикацией каталога и не включает товары в обычный поиск или подбор.

## Что обнаружено

Обычный backend `http://127.0.0.1:8000` из локального запуска использовал `C:\vscode\upgradeLab\.artifacts\local-run-20261111-af9b7c63\runtime.db`. В этой базе было 0 `CatalogProduct` Регарда и 352 старых `StoreOffer` Регарда; 0 из них проходили действующий 24-часовой TTL. `/api/offers/status` показывал 0 свежих предложений.

Последний локально импортированный owner-provided XLSX находился в отдельной базе `.artifacts/regard-download/etl/regard.analysis.db`. В ней 6 116 `CatalogProduct`, из них 5 991 присутствуют в последнем фиде; 125 записей помечены отсутствующими в последней выгрузке. Есть 3 037 связанных `StoreOffer`, но актуальных в последнем фиде — 2 986. Дата прайса: **10 ноября 2026, 14:30 UTC**. На момент проверки эти 2 986 записей укладывались в 24-часовое окно, но свежесть сама по себе не подтверждает текущую цену или наличие.

Для текущего файла в базе не указаны URL товара, URL фотографии или наличие ни у одной записи. Поэтому карточки используют текстовый placeholder, а ссылки на магазин не создаются. Во всей выгрузке наличие — `unknown`; автоматический подбор исключает данные, не прошедшие правила допуска.

На момент аудита последний импорт был младше 24 часов: **2 986** связанных с актуальными строками StoreOffer проходили временную границу TTL. Но через обычный публичный API доступно **0**: source rights и `in_stock` gate исключают эти строки. Новая local admin API показывает **5 991** текущую `CatalogProduct`, 60 на странице (до 100 по `limit`), из которых 2 986 имеют актуально связанную StoreOffer.

## Почему обычные карточки не появлялись

Были одновременно три причины:

1. Запущенный сайт смотрел на `runtime.db`, в которой самого каталога Регарда не было.
2. Импортированные товары лежали в отдельном `*.analysis.db`; это отдельная локальная база анализа, а не источник, автоматически подключаемый к backend.
3. Права разрешали `development=true`, но `public_display=false`, `public_enabled=0`, `commercial=false` и `automatic_download=false`. `available_offers()` применяет 24-часовой TTL и `filter_catalog()` не выпускает закрытый каталог в публичный API. Публичная история цены аналогично закрыта и отвечает 404.

Кроме того, в приложении раньше не было HTTP endpoint или UI для владельческого просмотра этих приватных строк. Импорт работал; путь импорта не был подключён к публичному каталогу.

## Новый локальный административный просмотр

Добавлен `GET /api/admin/catalog/regard` и `GET /api/admin/catalog/regard/{product_key}/price-history`. API включается только при наличии отдельного `REGARD_CATALOG_ADMIN_TOKEN`, TCP-клиент должен быть loopback, а подключённая SQLite обязана иметь суффикс `.analysis.db` и действующее development-разрешение Регарда. Ключ сравнивается constant-time, не записывается в логи и передаётся только заголовком. Ответы имеют `Cache-Control: no-store`. X-Forwarded-For не используется.

Предпросмотр открыт на **http://127.0.0.1:5174/?tab=search&regard_admin=1**. Обычный UI работает на **http://127.0.0.1:5173**; без `regard_admin=1` закрытая панель не отображается. Ключ для локального preview хранится только в игнорируемом Git файле `.artifacts/regard-admin-preview-20261111/admin-token.txt`; панель показывает путь, но не значение ключа.

Просмотр работает по отдельной проверенной копии `.artifacts/regard-admin-preview-20261111/regard.analysis.db`; исходный analysis DB и обычный runtime DB не изменялись. Право `public_display`, `public_enabled`, `commercial` или `automatic_download` не менялось. В production без ключа endpoint отвечает 404.

Карточка содержит исходное название, производителя (если есть), цену из payload XLSX, категорию, дату прайса, статус наличия/сопоставления, связанный `StoreOffer`, реальную ссылку/фото только если они были в выгрузке, иначе явный placeholder, и историю из таблицы 14-дневных наблюдений. Для `Ryzen 9 9900X` в копии показаны две реальные дневные цены: 35 990 ₽ (9 и 10 ноября); это исторические строки прайса, а не подтверждение текущей цены в магазине.

Снимок реальных карточек: [regard-admin-real-cards.png](../.artifacts/regard-admin-preview-20261111/regard-admin-real-cards.png). Источник строк — локальная копия XLSX импорта, синтетические UI fixtures не использовались.

## Permission gates

| Возможность | Текущее состояние |
| --- | --- |
| Ручной импорт owner-provided XLSX для development | Разрешён сохранённым локальным правом; импорт уже выполнен |
| Закрытый анализ / локальный owner view | Разрешён development-правом и отдельным локальным ключом |
| Публичный поиск и подбор по этому каталогу | Выключен: public display grant отсутствует, записи не публикуются |
| Публичная история цен | Закрыта; обычный endpoint отвечает 404 |
| Коммерческое использование | Не разрешено |
| Автоматическая загрузка прайса | Не разрешена; в preview также принудительно выключена |
| Ссылка на страницу товара / фото | В текущем XLSX не указаны; UI ничего не подставляет |

## Проверки

- Admin API: 200 с верным ключом, 403 без/с неверным ключом, 404 для не-loopback и для обычной SQLite, 422 для неподдерживаемого окна истории.
- Публичный `/api/offers/status`: 200, 0 свежих Regard offers; обычный `/api/offers/search`: 200, 0 предложений. Запросы к магазинам были выключены в preview.
- Публичная история для импортированного продукта: 404. Приватный endpoint истории: 200.
- Браузер: карточки настоящих импортированных строк, поиск Ryzen, категория CPU и дневная история проверены; внешних запросов не было.
- Новые backend тесты: 7 прошли. Полный backend suite: 583 прошли, 2 пропущены. Frontend: 99 прошли; production build прошёл.

Проверочный preview использует отдельные порты 8001/5174. Для остановки только preview процессов проверьте владельцев портов 8001 и 5174; обычное приложение продолжает работать на 8000/5173. Файлы токена, копии базы и скриншоты находятся в `.artifacts` и не предназначены для публикации.
