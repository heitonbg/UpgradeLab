Фото HTTPS/data хранится без серверной загрузки; CSS задаёт max-height, но не фиксированную область. Категория эвристическая, связанного hardware_id и статуса нет. Внешние источники: 12 адаптеров, общий safe_http; разрешение и live-доступность не подтверждены. Chromium/CDP заблокированы. City соответствия в магазинах отсутствуют. Все доступные источники не означает все зарегистрированные адаптеры.

## План и границы готовности

B. Независимый законченный блок биржи: офлайн-справочник городов, owner-only редактирование, контакты, фото, статусы, модель Hardware, раздельные даты и явное подтверждение продавца. Миграция только аддитивная. Старые объявления сохраняются; отсутствие города/подтверждения не угадывается. Никакого участия в оптимизаторе до C–E.

C. Общий geo-контракт: all/local/delivery; неизвестная география исключается из strict. Город и выбор источников проходят через формы/задания/ключ кеша/сохранения. Подтверждение доставки конкретного товара в конкретный город и цена доставки независимы от общероссийских цен.

D. Внутренний адаптер с прямым DB-доступом и доказательствами продавца; список разрешённых внешних интеграций. Не объявлять seller-подтверждение магазинной сверкой и не включать экспериментальную часть по умолчанию.

E. Подключение существующего оптимизатора через единый geo/quality слой; учёт известной доставки, неизвестные дополнительные расходы отдельно. Сохранение ссылок и исторических цен после удаления лота.

F. Регрессия после каждого блока, миграция на временной legacy SQLite, frontend production build и по возможности локальная визуальная проверка без разрешения сети Chromium. Не объявлять всю итерацию готовой по результатам только B.

Блоки C–E не должны появляться в интерфейсе как работающая функция до сквозных проверок.

## B. Реализованный независимый блок биржи

**Итерация 7 целиком ещё не завершена.** Готовы аудит A и блок B. C–E (географический контракт внешних предложений, внутренний источник оптимизатора, доставка и городские сборки/апгрейды) не включены и не обозначаются как работающие. Это граница независимого изменения из пункта 22 задания: финансовую интеграцию нельзя выдавать за готовую по результатам CRUD и городского фильтра.

### Справочник

backend/app/data/cities.json — стартовый офлайн-справочник из 21 населённого пункта, не полный перечень РФ. Идентификаторы ru:* принадлежат UpgradeLab и не выдаются за ФИАС/КЛАДР/ID магазинов. Есть название, регион, варианты написания и пустой external_ids. Советск различается по трём регионам. Unicode casefold/NFKC и ё/е; API /api/cities?q= возвращает до 30 подсказок, поддерживает точный ID. Расширение — добавление проверенных записей с уникальными неизменяемыми ID; frontend запрашивает поиск своего API с debounce, а не внешний геокодер.

Новые объявления требуют выбранный city_id на backend и frontend. Legacy-записи без города читаются и редактируются с неизвестной географией; город им не приписывается автоматически. Фильтр биржи сочетается с категорией, ценой, состоянием, типом сделки и строкой поиска; city сохраняется в URL. Город продавца сам по себе не является доказательством доставки, наличия или независимой проверки товара.

### Редактирование и данные

PATCH /api/listings/{id} проверяет ListingOwner до применения изменений; чужой/непринадлежащий лот возвращает 404. Поля id/user_id/created_at/updated_at/availability_confirmed_at нельзя задать через PATCH. Частичный ввод объединяется с текущими данными и заново валидируется до записи. Обмен без условий, неправильный город/фото/контакт/модель отклоняются без частичного обновления.

Создание и редактирование используют одну форму: предзаполнение, сохранение/ошибка/отмена, подтверждение закрытия при изменениях, beforeunload. Редактирование доступно в личном кабинете и подробностях своего объявления. Фото заменяется/удаляется. В текущем контракте остаётся одно фото, галерея из нескольких файлов не добавлена.

publication_status: active/sold/withdrawn. Проданные и снятые исключены из публичной выдачи и остаются в /my/listings. condition дополнен Неисправное. Это не включает товар в автоматический подбор: внутренний адаптер ещё не подключён.

category и hardware_id необязательны для обычного объявления. Каталог ищется локально по полученным CPU/GPU/RAM; выбор подставляет модель в заголовок. Backend проверяет тип Hardware и точную CPU/GPU-сигнатуру, включая суффиксы и мобильную GPU; связанная RAM требует названия выбранной модели каталога. Для остальных категорий каталога Hardware пока нет — можно указать категорию, но не выдуманную модель/характеристики. Наличие привязки не является независимой проверкой продавца.

### Даты и заявление продавца

created_at остаётся исходной датой публикации; updated_at меняется при редактировании. availability_confirmed_at устанавливается только явным confirm_availability. Изменение цены, города, категории, модели, названия, состояния, статуса/типа сделки сбрасывает подтверждение; описание/контакты/фото не продлевают его. sold/withdrawn снимают подтверждение.

Отдельная новая политика пользовательских заявлений — менее 24 часов: seller_declared/expired/not_confirmed/not_available. Это короткий консервативный срок заявления пользователя без независимой сверки; он не меняет 15-минутную магазинную проверку, магазинные TTL или complete/draft/partial. Заявление продавца не является магазинным verified и пока не используется оптимизатором.

Подбор и его кеши ещё не используют Listing, поэтому соответствующих финансовых кешей этого источника сейчас нет. Их версионирование/инвалидация по изменению/удалению/продаже обязательны в D–E; сторонние кеши и исторические сохранения не удалялись.

### Контакты

Одинаковая нормализация на Python и JS:
- iwrawww, @iwrawww, t.me/iwrawww, https://t.me/iwrawww → https://t.me/iwrawww;
- семь указанных форм российского номера → +79961234567 и tel:+79961234567;
- незавершённый телефон не сохраняется как полный;
- домен Telegram проверяется целиком; userinfo, чужой домен, произвольная схема не превращаются в контактную ссылку;
- форма даёт явный тип и предпросмотр «Написать в Telegram»/«Позвонить».

Для совместимости старого контракта нераспознанные свободные контакты и короткие @test без contact_type остаются текстом, без автоматически построенной ссылки. Явный telegram с коротким username отвергается. Новый UI требует корректный контакт; неизменённый старый контакт можно сохранить при редактировании. Legacy email поддерживается. Это осознанная совместимость, не утверждение о валидности старых контактов.

### Фото и визуальная проверка

ListingPhoto используется в карточке, подробностях и форме. Фиксированный контейнер 4:3, object-fit:contain, min-width:0 и overflow:hidden; сломанное изображение заменяется заглушкой. Подробности/форма открывают увеличение. Сервер не скачивает URL изображения; действуют прежние HTTPS/data JPEG/PNG/WebP ограничения.

Реальная локальная проверка Edge через Playwright выполняется отдельным trusted-app тестом, не через browser_offers. Runtime Chromium/CDP остаются заблокированы. Все API подменены, внешние URL блокируются, рабочая БД не открывается. Синтетические картинки: 80×600, 600×80, 300×300, 2400×1800 и сломанный длинный URL. Ширины 320/375/430/768/1280/1920; проверены отсутствие горизонтального overflow, область 4:3, увеличение, редактор, предупреждение отмены, телефон и город, PATCH payload. Это не доказательство live-интеграции или сетевой изоляции Chromium для сторонних страниц.

Артефакты: .artifacts/iteration7/visual-report.json и market-/edit-/zoom-*.png. Исполняемый тест: backend/tests/visual_marketplace_fixture.py. Он использует существующий локальный Edge; при отсутствии браузера нужен свой проверенный executable_path, зависимости автоматически не устанавливаются.

### Миграция

Три прежних столбца listing_type/exchange_for/photo_url также сохранены в идемпотентном helper. Колонки, строки, контакты и даты не удаляются и не переписываются.

Миграция проверена дважды на временной legacy SQLite и в smoke. Рабочая база проекта не мигрировалась в этой сессии. При последующем запуске create_app выполнит helper; перед production-обновлением нужна обычная резервная копия владельца. Формальный журнал миграций проекта этим изменением не введён.
