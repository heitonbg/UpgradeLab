# История цен Regard

Дневная цена прайс-листа не является подтверждённой текущей ценой магазина и не заменяет историческую стоимость сохранённой сборки.

`catalog_daily_prices`: составной ключ product_key/source_day, integer price_kopecks, source, import_key. История содержит последние **14 календарных дней источника**, а не последние 14 обновлений. Дата вычисляется из исходного timestamp, UTC-нормализации и явного смещения схемы; получение файла сегодня не переносит вчерашнюю цену на сегодня. Смещение +180 минут требует подтверждения источником. UTC/TTL предложений не менялись.

Один товар имеет одну итоговую цену на день. Коррекция в тот же день заменяет дневную цену и создаёт компактную запись `catalog_price_corrections` с прежними копейками/receipt. На следующий день неизменная цена записывается как новое наблюдение, только если изменилась исходная дата прайса. Повтор тех же байтов не создаёт наблюдений. Очистка выполняется в успешной транзакции импорта: cutoff = сегодняшний день источника − 13 дней. Неуспешный импорт ничего не очищает. Первичная запись legacy-аудита сохраняет полные данные, последующие обновления — изменения полей; полные ежедневные копии названий и характеристик не создаются. Старый аудит не переписывается. Квитанции native-импорта хранят число staged и выборку из 20, полный preview остаётся локальным диагностическим артефактом.

SavedBuild JSON, историческая стоимость и существующий механизм повторной сверки не изменяются. Current CatalogProduct не удаляется при отсутствии в новом файле: ставится missing_from_feed. Старые БД получают новые таблицы аддитивно, без изменения пользовательских строк.

## API и интерфейс

`GET /api/products/{catalog_product_id}/price-history?days=7` или `days=14`. Другие окна дают 422. Публичная выдача требует действительных public_display-прав, public_enabled и отсутствия fixture; иначе 404, включая отсутствие записи прав. История закрытого анализа не публикуется. Для карточки предлагается устойчивый catalog_product_id; внешний source ID не принимается вместо него.

В карточке предложения есть раскрываемая история 7/14 дней: точки по календарной оси и доступная таблица, минимум/максимум/среднее, изменение только при двух наблюдениях, исходные даты. Пропущенные дни не интерполируются, неизвестная цена не становится нулём. Для недоступной истории показывается понятное сообщение. Пустой интервал возвращает null-статистики и пустой список. График не вызывает запросов до нажатия пользователем.

Реальное наблюдение имеется пока за один день и один XLSX. Четырнадцать реальных дней не выдуманы; ёмкость и границы проверяются синтетическими локальными тестами. Цена прайса не подтверждает наличие, доставку или возможность покупки.

Измерение ёмкости: `python -m scripts.measure_history_capacity --products 4991 --output NEW.fixture.db` из backend. Только синтетические цены отдельной fixture, не магазин. 69 874 строки за 14 дней заняли 16 379 904 байта SQLite (15.62 MiB). Ни одна такая цена не поступает в реальный каталог.
