# Regard Daily Sync

Проверено 10.11.2026. Реализован офлайн-импорт и защищённый загрузчик; автоматический production-импорт **выключен**.

Источник XLSX найден в подвале [официального сайта](https://www.regard.ru/): `https://www.regard.ru/api/site/pricelist`. Первоначальная проверка вернула 403; повторная диагностика готовым Python-клиентом со стандартными заголовками получила настоящий XLSX/200. robots.txt проверен, явного запрета пути endpoint не найдено; документированные права регулярного использования/публикации пока не установлены. См. [диагностику загрузки](REGARD_DOWNLOAD_DIAGNOSTICS.md). [Юридическая информация](https://www.regard.ru/about/legal) сама по себе разрешением не считается. Защита не обходилась. Товарные URL и фотографии не подтверждены: ID из XLSX не превращается в предполагаемый URL. Используется существующая заглушка изображения.

## Запуск

Из `backend`, после резервного копирования и миграции схемы:

```powershell
.\.venv\Scripts\python.exe -m scripts.regard_sync --database C:\private\regard.analysis.db --schema C:\private\schema.json --rights C:\private\rights.json --file C:\private\price.xlsx --closed-analysis
.\.venv\Scripts\python.exe -m scripts.regard_sync --database C:\private\regard.analysis.db --status
```

Закрытый анализ допускается только на выделенной `.analysis.db`, аудитории development. Права оформляются по существующей `CatalogRights`: development/public_display/commercial/automatic_download, основание, подтвердившее лицо, UTC-дата. Разрешение владельца проекта на локальный анализ не является лицензией магазина на публикацию. Для применения к публичной БД необходимы отдельные документированные права; native XLSX без URL/наличия не публикуется автоматически.

Без `--file` загрузчик требует одновременно `REGARD_DOWNLOAD_ENABLED=true`, разрешение automatic_download в БД, существующее разрешение сетевой политики и точный подтверждённый endpoint в `REGARD_PRICE_URL`. Флаг не отменяет остальные проверки. На 401/402/403/404/429 повторов нет; максимум два запроса при временном серверном отказе/тайм-ауте. HTTPS, проверка DNS/IP, закрепление адреса, TLS и ограничения перенаправлений сохранены. Дополнительные MIME-типы XLSX разрешены только выделенной сессии загрузчика. Архив проверяется парсером и CRC. Минимум 1000 выбранных товаров для daily sync; меньшие синтетические входы разрешены только явным аргументом функции в тестах.

## Атомарность и повтор

OS-lock рядом с файлом SQLite исключает двух локальных исполнителей. BEGIN IMMEDIATE и существующая проверка отпечатков защищают применение каталога. Продукт сохраняет ключ source/external ID; отсутствующие в полном прайсе помечаются missing, не удаляются. Падение записи истории откатывает изменение текущих продуктов/предложений/квитанции. Журнал исполнения сохраняет failed отдельно; незавершённый предыдущий запуск помечается interrupted только после получения OS-lock. Нельзя запускать разные изолированные файловые копии как общую БД нескольких экземпляров.

Повтор пропускает XML-разбор только при совпадении байтов, схемы, прав, аудитории, режима, минимального размера, Hardware и состояния текущего каталога. Изменение любого условия требует обычной проверки. Воспроизведение старого успешного receipt не откатывает более новый каталог. Прайс старше последней успешной исходной даты отвергается. При подозрительном сокращении каталога обновление блокируется.

`tools/regard_daily.example.json` — неактивный пример: один исполнитель ежедневно 04:00 UTC (07:00 UTC+03). Это не утверждение о наличии scheduler Amvera. Конкретный механизм запуска нужно выбрать в доступной инфраструктуре. Приложение не запускает cron при старте каждого worker.

```powershell
.\.venv\Scripts\python.exe -m scripts.profile_regard_sync --file ..\.artifacts\regard-feeds\regard_price_091126_17.xlsx --output ..\.artifacts\regard-daily-profile-new
```

Каталог назначения обязан быть новым; рабочая БД не читается. Реальный файл: 4 571 355 байт, SHA-256 `3c385de0d58157bbf7240afd6920637e05cacadc86693d64d9162b0e1692ceb6`, дата 09.11.2026 17:30 с явно заданным смещением +180 минут. В файле часовой пояс не указан, это допущение оператора.

83 719 товарных строк всего, 4 991 строка восьми категорий. Сопоставление: matched 247, structured 2088, ambiguous 74, unmatched 2582. Закрытых материализованных предложений 2335; публичных 0. Дневных цен 4991. В `.artifacts/.../profile.json` сохраняются фактические время/RAM/размер БД и результат повтора. Первый предварительный прогон: 31.38 с, peak working set 164.08 MiB, SQLite 20 578 304 байта; итоговый профиль выполнен отдельно после оптимизации кеша. Это метрика процесса Windows, не обещание потребления Linux-контейнера.

Ограничения: сжатый файл ограничен 8 MiB и находится в памяти; XML обрабатывается потоком, но выбранные строки и подготовленный план материализуются. Нельзя заявлять полностью потоковое O(1) потребление памяти. Правила размеров/макросов/формул/DTD/ZIP-путей сохранены. Автоматическое скачивание технически подтверждено; регулярный production-запуск и реальные товарные карточки/фото пока не подтверждены.

Итоговый профиль после изменений: первый импорт 40.86 с, повтор 1.54 с с xlsx_parse_skipped=true, peak working set 163.89 MiB, SQLite 20 197 376 байт. Измерение параллельно с регрессией; не чистый performance benchmark. Закрытый офлайн-подбор на этом каталоге: reference/hybrid за 80 000 ₽ нашли восемь деталей на 74 850 ₽ (draft, покупка и технические неизвестные не подтверждены). Подробности в [итоговом отчёте](CATALOG_INTELLIGENCE_REPORT.md).

Текущий загрузчик использует потоковый SafeSession.get_to, постоянные стандартные Accept/Referer с User-Agent UpgradeLab/1.0, точный MIME и проверку native XLSX/CRC перед атомарным сохранением. Последние проверенные метрики и доступность: [REGARD_DOWNLOAD_DIAGNOSTICS.md](REGARD_DOWNLOAD_DIAGNOSTICS.md).


## Каталог, TTL и реальный E2E — 2026-11-11

Эта запись уточняет прежние ограничения закрытого каталога: владелец разрешил публичный некоммерческий показ данного прайса, automatic_download/commercial остаются отдельными правами. Regard catalog_import использует отдельное CATALOG_PRELIMINARY_HOURS=72: fresh до 24 часов, stale до окна — только предварительная оценка, затем historical. imported_at не заменяет дату цены; live TTL/подтверждение не продлены. Поиск, ручной выбор, автоматический подбор, upgrade и saved review используют этот контракт. Публичная витрина не отправляет пустой category; frontend разделяет in-flight hardware запрос. Права и database-bound analysis проверяются один раз на выборку без глобального кеша.
