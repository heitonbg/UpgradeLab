# Технические решения

## 2026-11-09 — первая итерация

- Сохранить монолит, SQLite и ограниченный worker: подтверждённой необходимости менять инфраструктуру нет.
- Сначала устранить расхождение CPU/чипсет в ручной сборке, переиспользовав cpu_board_matches из автоматической ветки.
- Для известного сокета платы проверять противоречие с запросом; отсутствие характеристики не заменять придуманным значением.
- Не менять формулу FPS, TTL цен и порядок источников в этой итерации.
- Не трогать рабочие БД, секреты и внешние сайты. Аудит не подтверждает юридическое разрешение на массовый сбор.
- Не вводить Alembic без отдельной проверки миграций на копии БД и процедуры восстановления.

## 2026-11-09 — итерация 2: время цен

1. Все сравнения времени цен выполняются в aware UTC. Старые naive значения трактуются как UTC по историческому контракту проекта. Недостающий исходный timezone не угадывается.
2. SQLite продолжает хранить naive UTC. На входе timezone нормализуется перед записью; данные не удаляются и не мигрируются массово.
3. Сохраняются существующие TTL и различие включительных/исключительных границ; правила приведены в ARCHITECTURE.md.
4. Сохранён 5-минутный допуск только для наблюдения из внешних источников. Самостоятельно записанные сервером timestamps проверки/кеша не допускаются из будущего.
5. Текущая подтверждённость выводится из фактического времени сверки, не из времени кеширования/сохранения. Историческое свидетельство остаётся историческим.
6. Исправляются только время и связанные состояния цен. Сохранённые JSON-снимки и их статус автоматически не пересчитываются; UX устаревших сохранений, SSRF и авторизация не входят в эту итерацию.
7. Новые зависимости, миграции и изменения дизайна не потребовались.

## 2026-11-09 — итерация 3: ограничения авторизации

- Сохранить scrypt, соль, cookie-сессии и reset-токены; доказанной необходимости менять их нет.
- Использовать атомарные SQLite UPSERT/RETURNING и прежнюю таблицу reset-счётчиков. Добавить только таблицу одноразовых краткоживущих разрешений.
- Общая квота email включает дополнительную работу клиента вместо жёсткой блокировки чужого аккаунта. Жёсткие IP/IP-email квоты остаются обязательными.
- По явному выбору владельца сохранить мгновенную регистрацию и прежний 409 для существующего email; остаточный риск enumeration документирован.
- Настройки доверия к Amvera не выдумывать. В приложении не разбирать X-Forwarded-For/X-Real-IP; использовать проверенный Uvicorn peer policy.
- Не менять SSRF, сохранённые цены, FPS и оптимизатор. Не выполнять коммит автоматически.


## Итерация 4 — SSRF (2026-11-09)

Не принимать Playwright routing за сетевую изоляцию. Использовать stdlib pinned HTTPS с существующим CA bundle Requests, без новых зависимостей. Browser fail closed независимо от флага; безопасная доступность HTTP предпочтительна запуску неограниченного Chromium.


## Итерация 6 — сохранённые цены (2026-11-09)

UL-005 исправлен: старый result больше не показывается как новый расчёт с текущими ценами. Исторические JSON/created_at/status не меняются при чтении или проверке. Новое сохранение добавляет price_snapshot v1; GET возвращает динамическую price_review. POST /api/builds/{id}/prices проверяет владельца и выполняет только локальную сверку StoreOffer, без сети/пересчёта/записи. Неизвестные и удалённые предложения не подтверждают сумму; ручные оценки и предполагаемая продажа отделены от покупки.

Личный кабинет различает историческую стоимость, последнее наблюдение и актуальную сумму; истечение зависит от серверных UTC-часов и монотонного времени браузера. Исходные локальные снимки больше не удаляются при новом расчёте по старым настройкам. TTL, FPS, совместимость, авторизация, поиск и complete/draft/partial не изменены.

Проверки: 24 новых backend-теста и 10 frontend-тестов. Полная backend-регрессия: 291 успешно, 2 пропущены (293 обнаружено); standalone smoke/recovery успешны. Frontend: 37/37; production build и git diff --check успешны. Реальные магазины и визуальные/e2e сценарии не проверялись. Полный контракт, файлы и ограничения: [SAVED_PRICES.md](SAVED_PRICES.md).
