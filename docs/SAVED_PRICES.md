# Сохранённые сборки: история и актуальность цен — итерация 6

Дата: 2026-11-09. Исправлен UL-005. Изменены только сохранения и представление их цен; FPS, совместимость, поиск, авторизация и TTL не переписывались.

## Причина

POST /api/builds заново рассчитывает конфигурацию на сервере и сохраняет config/result в SavedBuild.data. GET раньше возвращал этот JSON, а AccountBuilds передавал его в обычные BuildResult/CalculatorResult. Сохранённые status=complete, price_verified_at, итог и within_budget не утрачивали видимость актуальности с возрастом. Дата created_at рядом с результатом этого не устраняла.

StoreOffer хранит последнее наблюдение по URL. Повторная сверка может изменить его цену и метаданные; last_verified_price хранит последнее доказательство, а не полный временной ряд. HardwarePrice и рыночные оценки апгрейда имеют собственные сроки и не равны подтверждённой цене покупки. Снимок сборки — отдельная историческая запись; переписывать его вслед за StoreOffer нельзя.

Кроме того, старый перенос localStorage выполнял новый серверный расчёт по config, затем удалял исходную запись браузера. Это заменяло историческое значение новым расчётом. Теперь действие прямо названо созданием нового расчёта, а исходные локальные данные остаются на месте.

## Контракт

Новые сохранения дополнительно записывают price_snapshot.version=1: выбранные компоненты, исторические суммы, идентификатор/URL/название предложения, даты наблюдения и подтверждения, если известны. Alternatives и ожидаемая выручка от продажи не считаются покупками. Результат и его исходный status сохраняются без изменений.

GET /api/builds добавляет вычисляемый price_review, не обновляя SavedBuild.data, created_at или StoreOffer:
- historical_total — сохранённая total_price полной сборки либо avg_price апгрейда;
- items[].historical_price / observed_at / verified_at — исторические данные;
- latest_price / latest_observed_at — последнее доступное серверное наблюдение; если предложение удалено, сохраняется последнее известное наблюдение из снимка с явным state=missing;
- confirmed_price / confirmed_at / valid_until — действующая оценка по текущим серверным данным;
- current_total — сумма только при полном покрытии сохранённой стоимости и достаточных данных обо всех покупаемых деталях; иначе null;
- evaluated_at — время оценки по общим UTC-часам; check_method=local_observations.

Исторический total может отличаться от current_total после изменения цены. Эти значения не подменяют друг друга. Сумма не признаётся актуальной по пустому списку offer_id или по части компонентов. Бюджет и остаток старого расчёта не пересчитываются незаметно; пользователь должен выполнить новый расчёт для нового решения о покупке.

## Свежесть и безопасность сопоставления

Используются прежние фильтры available_offers и UTC/TTL:
- наблюдение предложения: до 24 часов включительно, прежний допуск внешнего времени 5 минут;
- проверка страницы: менее 15 минут, на самой границе уже неактуальна;
- feed: прежнее специальное правило свежего наблюдения, без выдуманной проверки товарной страницы.

Недоступность не повышает статус: запись с price_verification.status=unavailable не подтверждает цену даже при origin=feed. Отсутствующие, невалидные или будущие checked_at страницы не подтверждают её. Повреждённые метаданные не мешают открыть исторический снимок: проверка актуальности отказывает консервативно.

Совпадения одного ID недостаточно: проверяются сохранённый URL, категория и имя/модель. Для legacy CPU/GPU допускается совпадение модельной сигнатуры вместо полного заголовка продавца, с проверкой явно указанного объёма GPU-памяти. Новые снимки сохраняют точное имя предложения; повторное использование URL/ID под другой товар не подтверждает старую сборку.

Ручная цена остаётся оценкой пользователя. Нулевая пользовательская стоимость детали сохраняется как отсутствие затрат на повторную покупку, без выдуманной рыночной цены и без утверждения, что владение проверено. Ненулевая ручная цена блокирует подтверждение всей покупки. Ожидаемая продажа своей детали показывается отдельно как историческая оценка выручки.

## Открытие и повторная проверка

Личный кабинет больше не использует обычные компоненты нового расчёта для старого снимка. Он явно разделяет историческую стоимость, последнее наблюдение и актуальную стоимость покупки. Исторический complete/draft/partial подписан как статус на момент расчёта, а не текущая гарантия.

POST /api/builds/{id}/prices проверяет владельца, возвращает тот же исторический снимок с новой price_review и Cache-Control: no-store. Изменений базы и сетевых запросов нет. GET также no-store. На открытой странице свежесть истекает по серверному evaluated_at и монотонному времени браузера; неверные часы устройства не продлевают подтверждение. UI обновляет оценку времени раз в секунду, после возврата к вкладке проверяет её при следующем рендере.

Для UpgradeLab пока нет подтверждённого разрешения на автоматическое получение данных магазинов. Поэтому кнопка называется «Проверить по серверным предложениям» и прямо объясняет, что к магазинам не обращается. Это сверка с уже полученными данными, не live refresh. Проверить ссылку можно вручную; ручной просмотр не меняет серверное подтверждение. После получения разрешённой интеграции обновление StoreOffer будет отражено при следующем чтении/проверке сохранения. Никакого скрытого вызова assemble/post_calculate/search/Playwright на открытии сохранения нет.

## Совместимость и данные

Миграция БД и массовая перезапись не нужны. Старые JSON без price_snapshot читаются через адаптер выбранных parts/upgrade_parts/upgrade_price. Если нет доказательств/даты/идентификатора, актуальность неизвестна; дата сохранения не заменяет дату наблюдения. Исходный JSON остаётся побайтно прежним после чтения и проверки.

Локальные снимки показывают историческую сумму и предупреждение. Создание новых серверных расчётов из их настроек оставляет оригиналы в localStorage. Это не перенос исходного исторического снимка между устройствами. Повторное действие может создать ещё один новый расчёт; исходные записи автоматически не удаляются.

Сохранение по-прежнему выполняет серверный расчёт, отклоняет partial и фиксирует фактическую конфигурацию. Проверка цен сохранения не меняет решение оптимизатора, FPS, совместимость или исходный complete/draft.
