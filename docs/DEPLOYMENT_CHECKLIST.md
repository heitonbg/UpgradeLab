# Deployment checklist: каталог и внешний поиск

Эта итерация не выполняла commit, push, deployment или миграцию рабочей SQLite.

1. Зафиксировать текущую версию приложения и конфигурацию без секретов. Убедиться, что SQLite расположена на постоянном диске и backend/привилегированный sync используют один и тот же путь. Не использовать относительный путь из разных рабочих каталогов.
2. Остановить писателей приложения на время изменения схемы. Подготовить резервную копию через SQLite online backup, а не копирование открытого .db без WAL.
3. Из backend явно выполнить на целевой БД только после проверки backup-пути:

```powershell
.\.venv\Scripts\python.exe -m scripts.migrate_catalog_intelligence --database C:\data\upgradelab.db --backup C:\backups\upgradelab-before-catalog.db --apply
```

Команда требует существующую БД, новый отдельный backup-путь, проверяет integrity_check копии и добавляет отсутствующие таблицы. Существующие строки не переписывает. Уже существующий backup не перезаписывается. Миграция проверена на старой синтетической БД, рабочая не мигрировалась. Для Linux использовать реальные абсолютные пути постоянного тома.

4. Проверить права файлов БД/lock/backup и доступ сервисного пользователя. Проверить восстановление копии на отдельном пути. Rollback: остановить писателей, вернуть прежнюю версию и проверенную копию вместе с согласованным состоянием SQLite; не смешивать старый .db с новыми -wal/-shm. Пробное восстановление production-backup в этой итерации не выполнялось.
5. Оставить REGARD_DOWNLOAD_ENABLED=false до документированного права автоматической загрузки и успешной проверки официального endpoint. HTTP 403 — причина остановки, не смены fingerprint/прокси/браузера. Права публикации/коммерческого использования отдельно от локального development.
6. Проверить ручной импорт файла на staging. Выполнить `--status` операторским CLI, проверить receipt/даты/missing/размер БД. Не публиковать закрытые файлы, XLSX, SQLite, .artifacts или секреты.
7. Настроить **одного** внешнего daily-исполнителя по неактивному примеру tools/regard_daily.example.json только после снятия блокеров. Не запускать scheduler в каждом FastAPI worker. Реальные возможности scheduler Amvera здесь не подтверждены. Контролировать succeeded/unchanged/failed/interrupted, время выполнения и актуальность исходной даты.
8. Backend-секрет OPENROUTER_API_KEY задаётся вне Git. Примеры .env содержат только пустой ключ. До испытаний поиска оставить SEARCH_ENABLED/ALLOW_PAID_WEB=false и денежный бюджет 0. Перед включением перепроверить model IDs, tools, тариф, права источников, настроить account/key spending cap и конечный дневной резерв. Наличие free LLM не делает tools бесплатными.
9. Проверить авторизованный явный запуск AI-задачи, владельца, 429, очередь, cooldown и истечение кеша. Оплата Web Search/Fetch и качество поиска ещё не проверялись. Нет гарантии exactly-once биллинга. Несколько backend с отдельными дисками не делят SQLite-бюджет; нужны общая координация и очередь до такого масштабирования.
10. Выполнить backend/frontend-регрессию, production build и git diff --check. После запуска проверить регистрацию/сессии/сохранения/биржу, offers/reference/hybrid и доступ с другого устройства. Интерактивный production smoke test и сетевой доступ из Amvera этой итерацией не выполнялись.

Публичный запуск автоматических реальных интеграций блокируют неподтверждённые права (локальный download/200 уже подтверждён), отсутствие подтверждённых товарных URL/наличия/фото и непроверенный платный поисковый сценарий. Это не блокирует локальный ручной анализ и существующие функции проекта.

Обновление: защищённый потоковый downloader реально скачал regard_price_101126_17.xlsx с HTTP 200. Это снимает прежний технический блокер локального скачивания, но не подтверждает сетевую доступность Amvera и права регулярной публикации. Подробности: [диагностика](REGARD_DOWNLOAD_DIAGNOSTICS.md).


## Каталог, TTL и реальный E2E — 2026-11-11

Эта запись уточняет прежние ограничения закрытого каталога: владелец разрешил публичный некоммерческий показ данного прайса, automatic_download/commercial остаются отдельными правами. Regard catalog_import использует отдельное CATALOG_PRELIMINARY_HOURS=72: fresh до 24 часов, stale до окна — только предварительная оценка, затем historical. imported_at не заменяет дату цены; live TTL/подтверждение не продлены. Поиск, ручной выбор, автоматический подбор, upgrade и saved review используют этот контракт. Публичная витрина не отправляет пустой category; frontend разделяет in-flight hardware запрос. Права и database-bound analysis проверяются один раз на выборку без глобального кеша. Подробные измерения, семь исправленных тестов, исходные даты, 12 реальных расчётов и инструкция Amvera: [FULL_PRODUCT_READINESS.md](FULL_PRODUCT_READINESS.md).
