# Правила работы с UpgradeLab

- Сначала изучить docs/REQUIREMENTS.md, docs/ARCHITECTURE.md и аудит; читать существующий код до изменений.
- Для подтверждённого дефекта сначала добавить воспроизводящий тест, затем внести минимальное исправление и запустить регрессию.
- Не подставлять вымышленные цены, характеристики и FPS; неизвестные значения сохранять неизвестными.
- Сохранять смысл complete/draft/partial и серверную проверку цены выбранного предложения.
- Не обращаться к реальным внутренним адресам в SSRF-тестах; использовать моки.
- Не обходить CAPTCHA и ограничения источников; доступ к API/фиду и разрешение на сбор подтверждать отдельно.
- Не читать и не публиковать секреты. Не изменять рабочую SQLite-базу при тестировании.
- Изменение алгоритма описывать в docs/CHANGELOG_DEV.md; обновлять документацию вместо создания дублей.
- Не создавать коммиты и не публиковать изменения без разрешения владельца именно для этого проекта. Не использовать force push.
