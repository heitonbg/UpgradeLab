## Апгрейд имеющегося ПК

Сценарий «У меня есть ПК» состоит из четырёх шагов: оборудование → задача → источники цен → проверка параметров.

- CPU и GPU выбираются из каталога с поиском без учёта пробелов и дефисов: например, `fx6100` или `rtx3060ti`. RAM можно задать вручную: тип, объём, канальность.
- Пользователь указывает игру, графику, желаемый FPS и бюджет. При необходимости включает учёт продажи старой детали и сценарий локальных нейросетей.
- Результат показывает вероятный ограничитель, центральный прогноз FPS до/после, прирост и примечания совместимости. Выбор замены и достижение цели в ветке апгрейда проверяются по центральному FPS. Диапазон доступен только как справка в пояснении расчёта и не определяет выбор. Модель отдельно показывает, как повлияет гипотетическое усиление CPU или GPU на 25%; это не измерение загрузки и не оценка качества сборки.
- Доступны до трёх карточек подходящих замен с FPS, ориентиром цены и источником. Если цель уже достигнута, покупка не предлагается автоматически, но варианты можно открыть для сравнения. Выбранный вариант сохраняется вместе с расчётом.
- Если текущая конфигурация уже достигает цели по модели, обязательная покупка не предлагается. Иначе выбирается наиболее доступная замена ограничивающей детали для достижения цели; при недостижимой цели — доступный прирост в бюджете.
- Замены с приростом меньше 5 FPS или 5% от текущего прогноза отбрасываются как слишком незначительные. Неизвестная цена не позволяет автоматически рекомендовать покупку при ограниченном бюджете.
- Для старой платформы или при отсутствии подходящей одиночной замены рассматриваются комплекты CPU + материнская плата + RAM + кулер. Все четыре позиции включаются в стоимость, текущая видеокарта остаётся. Для AM4 рассматриваются Ryzen 3000 и новее. При нехватке любой цены полный комплект не создаётся; при нехватке денег показывается сумма превышения бюджета.
- Одиночная замена CPU ограничивается подходящим сокетом; переход на другой сокет показывается отдельным комплектом платформы с платой, памятью и кулером. Оценка продажи берётся отдельно из Avito, независимо от магазинов для покупки; можно указать ожидаемую цену вручную. Автоматически учитывается продажа только заменяемого CPU/GPU, без предполагаемой выручки за старую плату и RAM. В результате и карточках показаны свои деньги, ожидаемая выручка и сумма доплаты. Вариант выше общего бюджета недоступен для выбора до изменения бюджета.
- Если автоматическая оценка продажи не получена, она имеет статус «неизвестна», а не нулевую стоимость. Для вариантов дороже собственных денег показываются «Продажа не оценена» и нехватка именно собственных денег; окончательный вывод о бюджете после продажи откладывается. Из карточек можно повторить автоматический поиск или перейти к вводу ожидаемой цены. Названия AMD FX с пробелом или дефисом сопоставляются с каталогом; старые несопоставленные объявления учитываются при чтении, если модель распознана однозначно.
- Для оценки продажи достаточно одного подходящего объявления: оно показывается как «Цена одного объявления Avito» с датой и ссылкой, без обозначения средней. При неудачном прямом поиске используется поиск карточек по короткой модели (например `fx6100`) через поисковик с чтением страницы Avito. Для этого режима сетевое обновление ограничено 12 секундами; при недоступном объявлении число из поискового сниппета не подставляется.
- ИИ-режим предупреждает о нехватке VRAM; скорость работы конкретных нейросетей не моделируется.
- Из результата можно сохранить расчёт, найти модель на бирже или начать объявление о продаже старого компонента.

После объяснения bottleneck доступен необязательный мини-тест с вопросами и разбором ответов. Он помогает понять причину ограничения и не блокирует рекомендации.

## Сборка с нуля

Четыре шага: задача и бюджет → платформа и детали → площадки → проверка параметров.

Полный системный блок содержит **CPU, GPU, материнскую плату, RAM, SSD, БП, корпус и кулер**. Монитор, периферия, ОС, доставка и услуги сборщика в сумму не входят.

- Остальные детали подбираются автоматически либо задаются вручную, в том числе выбором конкретного предложения. Нулевая ручная цена допустима для уже имеющейся детали.
- Алгоритм проверяет стоимость всех восьми позиций, перебирает CPU/GPU и может освободить бюджет под плату и память за счёт более доступной видеокарты.
- Если смена платформы разрешена, рассматриваются AM4/DDR4, LGA1700/DDR4, LGA1200/DDR4 и AM5/DDR5; при бюджете до 40 000 ₽ также LGA1151/DDR4. Вручную можно выбрать LGA1700/DDR5. Платформу можно закрепить.
- Запрошенный минимальный объём RAM сохраняется. `2×8 ГБ` считается как 16 ГБ; один модуль допустим, но не получает расчётный бонус двухканальной памяти.
- Есть игровой, минималистичный и экономный профили корпуса. Выбор зависит от бюджета и предложений, а не от одной фиксированной модели.
- В модальном окне появляются от одного до трёх различных вариантов: рекомендуемый и доступные альтернативы по цене и FPS. Третья карточка не добавляется искусственно.
- В карточках показаны состав, исходные названия объявлений, источники, ссылки, цены, диапазон FPS, остаток бюджета и пояснения изменений платформы или распределения денег.

Сервер читает цену выбранного предложения из БД; браузер не может подменить её своим числом. Вместе с результатом сохраняется фактическая платформа. Сохранение повторно рассчитывает выбранную конфигурацию, поэтому не фиксирует условия покупки навсегда.

Подробности: [алгоритм сборки](docs/assembly-selection.md).

## Поиск комплектующих и цены

### Площадки и способы получения данных

Поддерживаются **Ozon, Avito, Wildberries, Яндекс Маркет, DNS, Ситилинк, Регард, OLDI, KNS, XCOM-SHOP, ОНЛАЙН ТРЕЙД и НИКС**. Реестр означает наличие адаптеров и поисковых ссылок; доступность зависит от ответа и разметки площадки.

| Способ | Как работает |
| --- | --- |
| HTTP | Сервер читает публичные страницы, JSON-LD Product/Offer, микроданные и известную разметку товаров |
| Браузер | Изолированный Edge/Chromium выполняет JavaScript и читает выдачу или страницу товара |
| Поисковая строка | Поисковик находит ссылки, затем цена проверяется на площадке. Число из сниппета не считается подтверждённой ценой |
| Ссылка на товар | После входа можно добавить конкретный URL с проверкой домена и товара |
| JSON-выгрузка | Необязательный локальный файл или настроенный HTTPS endpoint с нормализованными предложениями |

Автосборка запускает поиск сама. Отдельный раздел позволяет искать модель вручную, выбрать категорию и способ чтения. Браузерный запрос вручную допускает до трёх площадок. Готовый партнёрский поставщик данных не подключён; выгрузки являются дополнительным каналом, а не обязательной подготовкой перед каждым подбором.

### Порядок автоматического поиска

1. Читаются сохранённые реальные предложения с датами и источниками; применяются фильтры, проверяется возможность полного совместимого состава.
2. Если выбран Avito, ему отдаётся приоритет. В смешанной сборке учитывается число подходящих деталей Avito, затем FPS и стоимость. Это не требование купить все детали только там.
3. Проверяются разные модели и категории. При разрешённом переходе к другим магазинам поиск продолжается на доступных площадках.
4. Публичные цены выбранных товаров сверяются по конкретным страницам. При изменении цены подбор пересчитывается. Успешная сверка кешируется на 15 минут. Настроенные доверенные выгрузки используют собственную цену и дату без отметки чтения страницы магазина.
5. При отказах данные не теряются: сервис пробует предварительный состав по полученным наблюдениям, затем частичный результат.

Сетевая часть автоподбора имеет общий бюджет **45 секунд**. Категории комплектующих запрашиваются параллельно через доступные магазины; работа с БД остаётся последовательной. Avito получает короткую отдельную попытку, после которой поиск продолжается на остальных площадках. Расчёт вариантов и работа БД добавляют время: это не строгий предел длительности HTTP-запроса. Повторные обращения к заблокированным источникам ограничиваются.

### Состояния результата

| `status` | Значение |
| --- | --- |
| `complete` | Полный состав в бюджете с недавней сверкой публичных цен либо допустимыми ценами настроенной выгрузки. `purchase_ready: true` не означает бронирование или гарантию условий покупки |
| `draft` | Все восемь деталей по реальным наблюдениям за последние 24 часа, но актуальные цены и наличие не подтверждены. `purchase_ready: false`, сумма предварительная |
| `partial` | Полного состава нет: показаны найденные предложения, недостающие категории, поисковые ссылки и причины. Общей стоимости готового ПК и его FPS нет |

У `draft` предупреждение видно до выбора карточки, в результате и после сохранения. По каждой детали показано, была ли цена сверена ранее или получена только из объявления; старая сверка не обозначается как текущая. Предварительные сборки можно сохранить с пометками. `partial` нельзя сохранить как готовую сборку.

Наблюдения предложений действуют 24 часа, обычный кеш поиска — 10 минут. После остановки общим тайм-аутом допускается более ранняя повторная попытка. История успешной сверки сохраняется при последующем отказе доступа.

Для апгрейда, если разрешён Avito или нужна оценка продажи, сервер пробует обновить предложения текущих и нескольких подходящих моделей, ограничивая время поиска. По каждому CPU/GPU ориентир рыночной цены вычисляется по подходящим б/у объявлениям Avito за последние 7 дней после фильтрации и отсечения крайних выбросов. Это отдельный режим оценки цены; срок предложений для покупки в автосборке остаётся 24 часа. Средняя помечается как таковая при трёх и более наблюдениях; одно или два показываются как ограниченная выборка. Указывается количество, самая ранняя дата выборки и пример ссылки. Это цены объявлений, не подтверждённые цены сделок или гарантия наличия. Если таких данных нет, могут использоваться сохранённые котировки Avito за последние 30 дней с датой, количеством и пометкой архивной медианы. Для остальных моделей цена остаётся неизвестной или берётся из другого разрешённого источника; цены для всего каталога не придумываются.

### Зачем используется серверная база

SQLite хранит каталог моделей, сопоставление CPU/GPU с производительностью и полученные из интернета объявления с ценами, источниками и датами. Подбор работает по этому нормализованному набору, который пополняется сетевым поиском. Так можно сравнить совместимые варианты и сохранить найденное при следующем отказе магазина.

`seed_data.json` и игровые профили не являются полной актуальной базой товаров интернета. Неизвестная CPU/GPU без надёжного сопоставления может отображаться в поиске, но не получает чужой прогноз FPS.

Обычный расчёт с режимом «Все доступные, включая архив» также может использовать сохранённые котировки PassMark и срез Avito. При выборе конкретных площадок отсутствие цен не подменяется PassMark. Автосборка использует реальные предложения деталей; недостающие цены не вычисляются из баллов производительности.

Инструкции: [браузерный поиск](docs/browser-price-search.md), [выгрузки и импорт](docs/marketplace-feeds.md).

## Качество и совместимость

Фильтры действуют для новых и ранее сохранённых объявлений:

- Исключаются распознанные готовые ПК, ноутбуки, мобильные GPU, аксессуары, крепления, дефектные товары, доноры и предложения «под восстановление».
- Различаются модели и суффиксы: например, RTX 3060 и Ti. Объявления с разными GPU или несовпадающим VRAM не получают ошибочное сопоставление.
- Для GPU есть пороги подозрительно низких цен и сравнение с другими предложениями той же модели. Обмен и выкуп не считаются обычной продажей детали.
- БП, SSD и кулеры проверяются по поддерживаемым сериям и характеристикам. Одного известного бренда недостаточно; список серий расширяется в коде.
- БП и кулеры при автоподборе должны быть новыми. Мощность и класс охлаждения выбираются с учётом CPU/GPU; неизвестный дешёвый БП не принимается только ради завершения сборки.
- SSD — внутренний SATA 2,5″ или M.2 NVMe. Поддерживаются разные серии Samsung, Kingston, WD, Crucial, Lexar, Netac и KingSpec. Б/у SSD с Avito допустим с предупреждением о SMART, ресурсе и проверке ёмкости.
- NVMe выбирается при подтверждённом слоте M.2 2280 PCIe/NVMe конкретной платы. При неизвестном слоте выбирается SATA; один сокет или надпись M.2 не подтверждают совместимость.
- Проверяются сокет, тип и объём RAM, форм-факторы, поддержка сокета кулером и отдельные ограничения поколений Intel/чипсетов. Траты на остальные детали ограничены долями бюджета с возможностью перераспределения.

Это проверка доступных характеристик и эвристики. Подлинность и физическое состояние экземпляра не подтверждаются. BIOS, все разъёмы питания, длина GPU, высота кулера, кабели и конкретная ревизия требуют проверки перед покупкой.

Правила, серии и источники: [качество комплектующих](docs/component-quality.md).

## Игры и расчёт FPS

В каталоге **19 игр**: CS2, Dota 2, Cyberpunk 2077, GTA V, Fortnite, Valorant, Apex Legends, Red Dead Redemption 2, PUBG: Battlegrounds, Call of Duty: Warzone, Overwatch 2, Baldur’s Gate 3, Hogwarts Legacy, Starfield, Forza Horizon 5, The Witcher 3 Next-Gen, Helldivers 2, Resident Evil 4 Remake и Мир танков. Есть поиск игры.

Режимы: **1080p Low, 1080p High и 1440p High**.

FPS выводится центральной оценкой и диапазоном с объяснением метода. В `backend/app/data/game_benchmarks.json` есть 43 строки настольных GPU для девяти игр со ссылками на опубликованные тесты. Для RDR2 и RTX 2060 Super в 1440p High отдельно учтены две опубликованные точки. Прямые данные GPU используются при совпадении модели и режима; другие сочетания оцениваются интерполяцией, пересчётом настроек или моделью.

В ветке апгрейда для CS2 часть CPU сравнивается по относительным результатам [ComputerBase](https://www.computerbase.de/artikel/prozessoren/cpu-gaming-benchmarks-amd-ryzen-vs-intel-core.85869/): тест 2023 года проводился в 720p с RTX 4090. Относительные значения помогают отличать игровую скорость от многопоточного синтетического балла, но не выдаются за замер пользовательской конфигурации. Для близких CPU и отсутствующих моделей применяется приблизительный перенос; для остальных игр CPU оценивается синтетически. Показанный диапазон не сужается без новых данных о точности.

Для GPU в CS2 Low добавлена отдельная консервативная опора на [тест ComputerBase при 1080p Medium (2024)](https://www.computerbase.de/artikel/gaming/counter-strike-2-benchmark-test.87904/). Исходный Medium не выдаётся за измерение Low; отсутствующие GPU оцениваются переносом по синтетическому баллу. Это заменяет прежний произвольный синтетический потолок, который мог обрезать прогноз разных CPU на одинаковом FPS. Реальный предел связки и достижение 550 FPS этим переносом не подтверждаются.

В ветке апгрейда цель сравнивается с центральным прогнозом FPS: 420 FPS не достигают цели 550 FPS, даже если верхняя граница справочного диапазона равна 550. В автосборке по-прежнему используется нижняя граница диапазона. Диапазон отражает эвристический запас неопределённости, а не статистический доверительный интервал. RT, DLSS/FSR и генерация кадров не учитываются. У «Мира танков» пока нет подтверждённого набора измерений — это явно помеченный модельный прогноз.

Отдельные опубликованные тесты показаны для сравнения. Значения Ultra/максимальных настроек не подставляются как измерения High. Прогноз сервиса не заменяет тест конкретной связки CPU/GPU в текущей версии игры.

Методика и источники: [игровой подбор и FPS](docs/fps-and-gaming-selection.md).

## Аккаунт, восстановление и сохранения

- Регистрация по email и паролю сразу открывает сеанс. Есть вход, выход, изменение имени и пароля.
- Пароли — `scrypt`-хеши с солью. Случайный идентификатор сеанса передаётся в `HttpOnly` cookie; в БД хранится его хеш. Опция «запомнить» сохраняет вход на 30 дней.
- Смена и сброс пароля отзывают старые сеансы. Discord-вход и проверка Discord-роли удалены.
- Восстановление отправляет через SMTP одноразовую ссылку на 30 минут. В БД хранится SHA-256-хеш токена. Есть лимиты по email/IP и одинаковый ответ для существующего и неизвестного адреса.
- После сброса остальные ссылки аннулируются. Токен убирается из адресной строки при открытии формы.
- Сборки и расчёты доступны в аккаунте с другого устройства. Чтение и удаление ограничены владельцем.
- Новые результаты не записываются в localStorage. Старые браузерные сохранения можно перенести в аккаунт; неудавшийся импорт остаётся для повторной попытки.

Без SMTP реальные письма не отправляются: интерфейс сообщает недоступность восстановления. Ссылки не имитируются и не выводятся в API/логи. Доставка требует действующих настроек почтового провайдера.

## Биржа

Просмотр доступен без входа, публикация и удаление собственных лотов — после авторизации.

- Продажа и обмен с отдельным полем «Что хотите получить», включая услуги.
- Название, описание, состояние, цена/условия и контакт продавца.
- Фото JPEG/PNG/WebP до 1 МБ либо HTTPS-ссылка; загруженное фото хранится в SQLite.
- Поиск по названию, фильтры типа сделки, категории, состояния и цены, сортировка по новизне/цене, счётчики и сброс фильтров.
- Для обмена ценовой фильтр отключается. Есть подробная карточка, загрузка, пустая выдача и ошибка с повторной попыткой.
- Переход из рекомендации к поиску модели и предзаполнение объявления старой детали.

Биржа — доска объявлений с контактами. Оплата, доставка, безопасная сделка и внутренний чат не реализованы.

## Определение оборудования

В сценарии апгрейда можно скачать `UpgradeLab-detect.bat`, запустить на Windows и загрузить созданный рядом `UpgradeLab-hardware.json` либо вставить текст отчёта. Скрипт читает CPU/GPU и физические модули RAM через Windows CIM, не требует установки программ и сам ничего не отправляет по сети.

Объём RAM считается по установленным модулям, тип DDR — по SMBIOS, если он доступен. Количество модулей не используется для угадывания канальности. Есть дополнительное определение GPU через WebGL, если браузер раскрывает renderer. Найденные модели нужно проверить; ручной ввод остаётся доступен.

## Интерфейс

В обоих сценариях есть четыре шага с возвратом, проверкой полей и итоговым просмотром параметров. При переходе в кабинет конфигурация сохраняется в состоянии приложения.

Используются тёмная тема с золотистыми акцентами, адаптивные сетки, отдельные карточки деталей, модальное сравнение, визуализация bottleneck и анимации появления. Загрузка сопровождается индикатором, временем ожидания и подсказками; это не точный процент готовности внешних площадок. Учитывается `prefers-reduced-motion`.

## Запуск на Windows

Нужны **Python 3.11/3.12, Node.js 20+ и npm**. Backend и frontend запускаются в двух отдельных терминалах PowerShell. В каждом блоке сначала указан переход в нужную папку. Путь `C:\vscode\upgradeLab` замените, если проект лежит в другом месте. Активировать venv не требуется.

### 1. Backend

**Обычный запуск, когда зависимости уже установлены:** скопируйте обе строки целиком в PowerShell. Они работают независимо от того, в какой папке сейчас открыт терминал.

```powershell
Set-Location "C:\vscode\upgradeLab\backend"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Если в приглашении терминала уже написано `PS C:\vscode\upgradeLab\backend>`, достаточно второй строки. Внутри `backend` путь к Python — **`.\.venv\Scripts\python.exe`**. Повторное добавление `backend` к пути обращается к другому каталогу `backend\backend` и может запустить неправильное окружение.

Дождитесь сообщения `Uvicorn running on http://127.0.0.1:8000`. Оставьте терминал открытым. Проверка сервера: **http://127.0.0.1:8000/api/health** — ответ `{"status":"ok"}`. Документация API: **http://127.0.0.1:8000/docs**.

Остановка — `Ctrl+C` в терминале backend. После изменения Python-кода остановите и запустите сервер заново. Для разработки можно добавить `--reload` в конец команды.

**Только для первой установки:** если файла `.venv\Scripts\python.exe` ещё нет, подготовьте окружение и зависимости. Если окружение уже существует, пропустите строку создания venv.

```powershell
Set-Location "C:\vscode\upgradeLab\backend"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если используете установленный `uv`, альтернативная подготовка окружения:

```powershell
Set-Location "C:\vscode\upgradeLab\backend"
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
```

После подготовки выполните команду обычного запуска выше. При первом старте создаются таблицы и загружается каталог, если он пуст. При необходимости настройте `backend/.env` по [образцу](backend/.env.example), сохранив существующие настройки. Для базового запуска файл не обязателен.

### 2. Frontend

Во втором терминале:

```powershell
Set-Location "C:\vscode\upgradeLab\frontend"
npm.cmd install
npm.cmd run dev
```

Откройте **http://localhost:5173**. Vite перенаправляет `/api` на `http://127.0.0.1:8000`. Не смешивайте `localhost` и `127.0.0.1` при работе с одним сеансом аккаунта. Остановка серверов — `Ctrl+C` в каждом терминале; повторная установка зависимостей для обычного запуска не требуется.

### 3. Браузерный поиск

В отдельном терминале установите браузерные зависимости:

```powershell
Set-Location "C:\vscode\upgradeLab\backend"
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
```

По умолчанию используется установленный Edge (`OFFERS_BROWSER_CHANNEL=msedge`). Если Edge нет, установите Chromium и задайте пустой `OFFERS_BROWSER_CHANNEL=` в `backend/.env`:

```powershell
Set-Location "C:\vscode\upgradeLab\backend"
.\.venv\Scripts\python.exe -m playwright install chromium
```

После изменений перезапустите backend. Без браузерных зависимостей HTTP-поиск доступен, но браузерный этап работать не сможет.

### Если backend не запускается

- При `WinError 10013` попробуйте другой разрешённый свободный порт, например `--port 8001`. В терминале frontend перед `npm.cmd run dev` задайте `$env:API_PROXY_TARGET='http://127.0.0.1:8001'`.
- Если порт занят, остановите ранее запущенный экземпляр своего сервера либо выберите другой порт.
- Если команда Python «не распознана», сначала выполните `Set-Location "C:\vscode\upgradeLab\backend"`, затем используйте `.\.venv\Scripts\python.exe`. Не добавляйте второй `backend` к пути.
- При `No module named uvicorn`, `requests` или `fastapi` установите `requirements.txt` в этом же окружении: `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`. Альтернатива с `uv`: `uv pip install --python .venv/Scripts/python.exe -r requirements.txt`.
- Если `/api/health` не открывается, проверьте ошибку в терминале backend. Frontend не запускает сервер API автоматически.

## Настройки и данные

Настройки читаются из `backend/.env` и переменных окружения. Образец: [backend/.env.example](backend/.env.example).

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | База; по умолчанию абсолютный путь к `backend/pc_upgrade.db`, независимо от рабочей папки |
| `CORS_ORIGINS` | Разрешённые адреса frontend через запятую |
| `COOKIE_SECURE` | Для HTTPS-развёртывания — `true` |
| `FRONTEND_URL` | Адрес сайта, доступный получателю ссылки восстановления |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SECURITY` | Почта; обычно `starttls`/587 или `ssl`/465, `none` — локальный тестовый SMTP |
| `OFFERS_LIVE_SEARCH` | HTTP-поиск публичных страниц, по умолчанию `true` |
| `OFFERS_FEED_FILE`, `OFFERS_FEED_URLS`, `OFFERS_FEED_TOKENS` | Необязательные выгрузки и токены их endpoint |
| `OFFERS_BROWSER_ENABLED`, `OFFERS_BROWSER_CHANNEL` | Включение браузера и канал |
| `OFFERS_BROWSER_CDP_URL` | Подключение к отдельному локальному браузеру; иначе контексты запускаются автоматически |
| `OFFERS_BROWSER_TIMEOUT_MS`, `OFFERS_BROWSER_PRODUCT_LIMIT`, `OFFERS_BROWSER_SEARCH_ENGINE` | Тайм-аут, число карточек, поисковик: `bing`, `google`, `yandex` |
| `API_PROXY_TARGET` | Адрес backend для Vite, задаётся в окружении процесса frontend |

На сервере хранятся аккаунты, хеши паролей/токенов, сеансы, восстановление, сборки, объявления, загруженные фото, котировки и результаты поиска. Для переноса данных нужно сохранять серверную БД; очистка браузера её не удаляет. При запуске старой БД новые поля объявлений добавляются без удаления лотов. Полноценной системы версионируемых миграций пока нет.

`.env`, рабочая БД, окружения, браузерные профили и `.artifacts/` исключены из Git. Для размещения нужны HTTPS, резервное копирование и SMTP для восстановления пароля. Если frontend и backend размещены отдельно, укажите `VITE_API_BASE_URL` и настройте CORS; при общем домене вместо этого можно проксировать `/api`. Vite dev server не является производственным развёртыванием.

## Служебные команды

Из каталога `backend`:

```powershell
# Список площадок и поиск модели
.\.venv\Scripts\python.exe -m scripts.collect_offers --list-sources
.\.venv\Scripts\python.exe -m scripts.collect_offers "RTX 5060" --sources avito regard oldi kns --method http
.\.venv\Scripts\python.exe -m scripts.collect_offers "RTX 5060" --sources avito dns --method browser

.\.venv\Scripts\python.exe -m scripts.import_offers offers.json

# Обновление архивных цен и сокетов
.\.venv\Scripts\python.exe -m scripts.refresh_prices

# Постепенно собирать цены Avito для каталога (следующий offset выводится скриптом)
.\.venv\Scripts\python.exe -m scripts.collect_avito_prices --category all --limit 25 --offset 0
```

`refresh_prices` получает публичные котировки PassMark с переводом USD в RUB по курсу Банка России и может импортировать подходящие записи имеющегося `avito_prices.db`. Зарубежная розница и сохранённый срез Avito не равны текущей российской цене покупки. Для таких котировок действуют сроки 7 дней для розницы и 30 дней для вторичного рынка; покрытие видно в `/api/prices/status`.

## Проверки

Из корня проекта:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p "test_*.py"
.\backend\.venv\Scripts\python.exe backend/tests/test_smoke.py
.\backend\.venv\Scripts\python.exe backend/tests/test_recovery_offers.py
```

Два интеграционных сценария запускаются отдельно; при unittest discovery они намеренно пропускаются. Тесты используют временные или изолированные БД и имитации внешних ответов. Их успех не подтверждает текущую доступность магазинов или реальную доставку SMTP-письма.

Проверяются расчёты, варианты сборок, бюджет, смена платформы, RAM, фильтрация объявлений, SSD/БП/кулеры, сверка цен, браузерный разбор, отказ площадок, сохранение предварительного результата, игровые основания, регистрация, восстановление, права владельца и миграция объявлений.

Во `frontend`:

```powershell
npm.cmd test
npm.cmd run build
```

Дополнительно есть `frontend/scripts/ui-smoke.mjs` для отдельного запущенного Edge с DevTools-портом 9223 и открытым frontend. Нужен Node.js с глобальным WebSocket, например 22+. Настройки: `UI_DEBUG_PORT`, `UI_BASE_URL`; дополнительные сценарии — `UI_PROJECT_CHECK=1`, `UI_AUTH_CHECK=1`, `UI_RECOVERY_CHECK=1`. Скрипт может создавать тестовые аккаунты, сборки и лоты: используйте отдельную тестовую БД.

## Ограничения и дальнейшая работа

- Площадки могут отвечать CAPTCHA, 401/403/429/439 и менять разметку. Обход CAPTCHA, смена IP и использование личных авторизованных браузерных профилей не реализованы.
- Полный результат возможен при наличии подходящих реальных наблюдений. На пустой базе предложений при недоступных площадках сервис не выдумывает цены и детали; возможен `partial`.
- Предварительная сумма не гарантирует покупку в бюджете: наличие, регион, доставка, скидки и актуальная цена требуют проверки.
- Для части игр/GPU нет прямых измерений, CPU оценивается моделью. Для повышения точности нужно расширять набор сопоставимых игровых тестов.
- Полная проверка BIOS, разъёмов, габаритов, состояния и подлинности товаров не реализована. Каталог проверенных серий ограничен.
- PDF-экспорт, отдельный экран сравнения сохранённых сборок, платежи, чат и доставка пока не реализованы. Модальное сравнение вариантов автосборки уже есть.
- Для публичного запуска остаются инфраструктурные задачи и эксплуатационная проверка.

Подробные документы: [подбор сборок](docs/assembly-selection.md), [качество деталей](docs/component-quality.md), [FPS](docs/fps-and-gaming-selection.md), [браузерный поиск](docs/browser-price-search.md), [формат выгрузок](docs/marketplace-feeds.md).

## Деплой frontend и backend в отдельных приложениях Amvera

В репозитории добавлены отдельные конфиги: `frontend/amvera.yaml` собирает React/Vite в статический сайт, а `backend/amvera.yaml` собирает Docker-образ FastAPI с Chromium и подключает постоянное хранилище `/data`. Для связи используйте HTTPS-домены одного сайта, например `https://upgrade.example.ru` и `https://api.example.ru`.

### Адрес API

Перед первой публикацией замените `https://api.example.ru` в `frontend/.env.production` на публичный HTTPS-домен приложения backend. Это единственное место в frontend, которое нужно менять при смене API-домена. После изменения frontend нужно пересобрать и повторно опубликовать.

Для локальной разработки `VITE_API_BASE_URL` не задан: запросы остаются относительными и идут через Vite proxy на `http://127.0.0.1:8000`. В собранном приложении запросы используют заданный `VITE_API_BASE_URL`, включая автоматическое определение GPU. Запросы отправляют cookies авторизации.

### Создание двух приложений

Amvera ожидает `amvera.yaml` в корне каждого приложения. Так как исходный репозиторий монорепозиторий, отправляйте содержимое `backend` и `frontend` в отдельные репозитории приложений Amvera через Git subtree. Сначала добавьте remote-адреса, которые Amvera показывает для каждого приложения:

```powershell
git remote add amvera-backend https://git.amvera.ru/USER/BACKEND_PROJECT
git remote add amvera-web https://git.amvera.ru/USER/WEB_PROJECT
```

Затем из корня UpgradeLab отправьте первую версию:

```powershell
git subtree push --prefix=backend amvera-backend master
git subtree push --prefix=frontend amvera-web master
```

Перед этим закоммитьте подготовленные файлы в локальный Git. Для обновления повторяйте эти две команды после коммита изменений. Если в проекте Amvera выбрана ветка `main`, замените `master` на `main` в соответствующей команде. Не создавайте два `amvera.yaml` в корне монорепозитория: конфиги уже находятся в корнях своих приложений и попадут туда при отправке subtree.

### Настройки приложения backend в Amvera

Создавай backend как приложение **Docker**. В корень backend-загрузки должны попасть `Dockerfile`, `.dockerignore` и `amvera.yaml` вместе с кодом. В Dockerfile используется официальный образ Playwright с Chromium, версия которого совпадает с установленным Python-пакетом; Amvera поддерживает Dockerfile и `persistenceMount` в `amvera.yaml` ([документация Amvera](https://docs.amvera.ru/applications/configuration/docker.html), [Playwright Docker](https://playwright.dev/python/docs/docker)).

В разделе переменных приложения задайте:

| Переменная | Значение |
| --- | --- |
| `FRONTEND_URL` | Полный HTTPS-адрес сайта, например `https://upgrade.example.ru` |
| `CORS_ORIGINS` | Тот же точный origin сайта, без завершающего `/` |
| `COOKIE_SECURE` | `true` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SECURITY` | Данные почтового сервиса, если нужно восстановление пароля |
| `OFFERS_BROWSER_ENABLED` | `false` — запуск заблокирован до проверки сетевой изоляции |
| `OFFERS_BROWSER_CHANNEL` | пустое значение — использовать Chromium из образа |

В Amvera переменные окружения нужно добавить через панель приложения; файл `.env.amvera.example` — шпаргалка. Сохраняйте `OFFERS_BROWSER_ENABLED=false`: наличие Chromium в образе не обеспечивает изоляцию сети. Пароли SMTP храни как секреты. При `AMVERA=1` проект автоматически выбирает SQLite-файл `/data/pc_upgrade.db`; `backend/amvera.yaml` подключает для него постоянный каталог `/data`. Для реальных пользователей включи резервные копии хранилища.

### Порядок публикации и проверка

1. Создайте два приложения Amvera из отдельных Git remote и опубликуйте backend.
2. Добавьте backend-домен, например `api.example.ru`, и настройте переменные backend. Проверьте `https://api.example.ru/api/health` — ожидается `{"status":"ok"}`.
3. Подставьте этот домен в `frontend/.env.production`, затем отправьте frontend subtree.
4. Добавьте frontend-домен и откройте сайт. Проверьте загрузку каталога, регистрацию, вход, обновление страницы с активной сессией и выход.
5. Если домены на разных хостах, внесите frontend origin в `CORS_ORIGINS`. Для cookies используйте HTTPS на обоих доменах; предпочтительны собственные sibling-поддомены одного домена.

В апгрейде сервер ищет замены по игровому приросту, включая X3D для CS2; обычная розничная цена не отменяет попытку поиска на Avito. Оценка продажи относится к заменяемому CPU или GPU. На HTTP-поиск и браузер выделяется общее сетевое окно 45 секунд. В результате показаны статусы выбранных площадок и кнопка обновления цен; сохранённая оценка отличается от нового ответа. Наблюдения до семи дней могут использоваться в оценке цены. Dockerfile устанавливает совпадающие версии Playwright и Chromium; на Linux используется встроенный браузер, даже если осталась настройка `msedge`. `/api/offers/status` содержит диагностику установки браузера. Используются публичные страницы и бесплатный поиск ссылок через Google, Яндекс, Bing и DuckDuckGo. Внешних платных API и подписок для поиска нет. Если площадка требует CAPTCHA, автоматическое чтение её цен может быть недоступно; в незавершённом подборе остаются найденные детали, бюджет на недостающие и прямые ссылки на магазины и поисковики. [Как работает эта версия](docs/free-search.md).

Длительный подбор из интерфейса запускается через `POST /api/search-jobs`: ответ `202` с номером задачи возвращается сразу. Фронтенд опрашивает `GET /api/search-jobs/{id}`, поэтому весь поиск не зависит от одного длинного HTTP-соединения через Amvera. При сетевом сбое повторный запуск с тем же идентификатором не создаёт дубликат. Результаты сохраняются в SQLite; номер активной задачи хранится в текущей вкладке браузера. Перезапуск самого backend прерывает выполнявшийся поиск и показывает понятную ошибку; уже завершённые результаты сохраняются. Используйте одну реплику backend: очередь выполняет одну задачу подбора одновременно и принимает до четырёх активных задач. Redis и отдельный платный worker не требуются.

Перед запуском браузера пробуется бесплатное чтение поисковых ссылок по HTTP, включая RSS-выдачу Bing. Цена берётся только с точной страницы товара. `OFFERS_HTTP_WORKERS=2` ограничивает одновременный разбор страниц для небольшого контейнера; также облегчён разбор структурированных предложений без построения всего DOM поисковой страницы. Поле `search_revision: server-jobs-http-v2` в `/api/health` подтверждает загрузку этой версии. Обычное открытие `/api/assemble` в адресной строке отправляет GET и закономерно получает 405: синхронный API принимает POST, а интерфейс использует задачи.

Результаты проверки поиска на развёрнутом backend, ограничения и команды диагностики: [Поиск на Amvera](docs/amvera-search-diagnostics.md). Поиск выполняется на сервере. При пустой выдаче выбранного поисковика браузер последовательно пробует другие поисковики; цены подтверждаются только на страницах товаров. `/api/offers/status` показывает число сохранённых предложений отдельно от последнего ответа площадки (`last_search`).
